# P12-05 앱 전송 큐

원본 계획 P12-05 / 요구사항 R050·R068·R073. 정보 동기화의 정상 전송 뒤 UploadDispatcher가 한 번에 최대 2개를 처리한다. 앱 main의 RepositorySyncBackend에 실제 HttpUploadTransport를 연결했다.

- 계정별 SQLite v10 local_upload_queue에 요청 ID·시도 ID·재발급 요청 ID·검사된 파일 명세·상태·재시도 횟수를 보존한다. URL/토큰은 저장하지 않는다. v1~9에서 보존 이관하며 복구 내보내기에 큐도 포함한다.
- 서버 승인본 ACTIVE/SAVED 및 로컬 검증 파일의 크기·체크섬 일치가 선행이다. 미승인/미해결 녹음 정보가 있으면 전송하지 않는다. 해결된 원본 이력은 기존 readMappingEligibility 검증으로 구분하며 존재만으로 영구 차단하지 않는다. 서버 보관 대상 여부는 실제 승인 API에서 최종 확인한다.
- 고정·고정 교체 우선, 그 뒤 큐 요청순. 최신 캐시가 있는 슬롯은 오래된 스냅샷 슬롯으로 덮어 판단하지 않는다. PIN 우선순위는 힌트이며 서버 업로드 승인 권한을 대신하지 않는다.
- 최초 요청과 재발급은 영속 멱등 키를 사용한다. 응답 유실은 같은 요청으로 재시도하며, 시도가 알려진 뒤 새 PUT 주소가 필요하면 재발급한다. 10분 주소와 24시간 시도 만료를 구분한다.
- 일반 전송 장애는 1·5·15분 후 최대 3회 자동 재시도한다. 401/403 승인 오류·한도·유효성 오류는 자동 반복하지 않는다. 프로세스가 SENDING 중 종료되면 RETRY/INTERRUPTED로 보존하고 직접 재시도가 필요하다. 횟수는 재시작·직접 재시도로 초기화하지 않는다.
- 계정 임대와 claim ID를 API 전송·응답 처리·파일 청크 전송마다 대조한다. 취소·계정 전환 후 늦은 결과를 다른 계정에 반영하지 않는다. 네트워크에서 이미 전송된 바이트까지 회수하는 의미는 아니다.
- 파일 전송은 원본을 읽기만 한다. 실패·취소·인증 만료로 파일/녹음 정보/저널을 지우지 않는다. 로컬 원본 부재는 BLOCKED로 보존한다.
- PUT URL은 HTTPS의 R2 계정 호스트만 허용하고 리디렉션을 따르지 않는다. 앱 Bearer 토큰은 API에만 전송한다.
- 성공한 PUT은 UPLOADED로 남긴다. 이 상태는 서버 STORED가 아니며 P12-06 완료 요청·검증 연결을 기다린다. UI 업로드 관리 화면과 운영 백그라운드 전송 정책은 해당 후속 계획 범위다.

검증 도구: `tool/verify_upload_queue.dart`는 기존 verification flavor에 설치하는 별도 합성 검사 화면이다. 실제 계정·녹음·서버 업로드는 건드리지 않고 휴대폰 SQLite/파일 보존을 확인한다. 실제 R2 서명 PUT은 P12-04에서 별도 통과했다.
