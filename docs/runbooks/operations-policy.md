# P24-02 초기 운영 설정

원본 계획 p01039–p01040, 설계 14.1·R121·R122. 검증 환경에 적용하며 공개 운영 배포는 별도 확인한다.

| 배포 설정 접미사 `songrecord.operations.` | 초기값 | 신규 제한 |
|---|---:|---|
| beta-accounts | 20 | 기존 계정 유지, 신규 가입만 `503 BETA_CAPACITY_REACHED` |
| pinned-limit | 10 | 신규 계정 UserEntitlement 기본값, 기존 개별 설정 보존 |
| personal-bytes | 1000000000 | 신규 계정 기본값, 기존 사본·개별 설정 보존 |
| global-bytes | 20000000000 | 실제 최종 사용량+예약량, DB 정책과 더 작은 한도로 신규 예약 차단 |
| daily-upload-bytes | 104857600 | UTC 일별 승인량, 기존 시도 재사용은 중복 차감하지 않음 |
| urls-per-minute | 10 | 최초·실제 URL 재발급의 최근 60초 사용량 |
| upload-concurrency | 2 | 활성 업로드 시도 슬롯, 이미 진행 중인 시도는 유지 |
| temporary-bytes | 536870912 | 실제 관측 임시 공간이 한도 이상이면 새 예약 잠금 |
| worker-concurrency | 2 | 모든 다운로드·검증 인스턴스가 공유하는 슬롯 상한 |
| worker-seconds | 60 | 다운로드·검증·확정 전체의 단일 기한, 중첩 단계가 다시 시작하지 않음 |

staging 파일에서 `SONGRECORD_OPERATIONS_` 대문자 환경변수로 연결한다. 배포 시작 때 해석·검증하고 재배포로 적용한다. 기존 DB를 초기화하거나 기존 사용자 한도를 덮어쓰지 않는다. 현재 스키마와 검증 기한의 상한을 넘는 확대는 거부하며, 향후 확대는 관련 마이그레이션과 재검토가 필요하다.

베타 입장은 새 계정 생성 전 global 행 잠금·현재 계정 수 확인·로그인 식별자 재조회로 API 인스턴스 간 마지막 자리 경쟁을 직렬화한다. 삭제 처리 중 계정도 실제 행이 남아 있으면 자리로 계산한다. 기존 로그인·계정 삭제 전용 기존 소유 확인에는 신규 입장 제한을 적용하지 않는다. 베타 입장 제한은 staging/prod 실제 배포 구성에서 연결하며 dev 합성 검증과 분리한다.

업로드 제한은 예약·승인·실제 URL 발급에만 연결된다. 정보 저장/수정/동기화·로컬 녹음·기존 조회/재생·삭제·내보내기·허용된 백업 다운로드·고정 해제를 전역 잠금하지 않는다. 정책을 낮춰도 기존 시도·서버 사본·로컬 원본을 삭제하지 않는다. 작업자 슬롯 설정은 작업 시작 전 초기화하며 진행 중인 검증에서 재설정하지 않는다.
