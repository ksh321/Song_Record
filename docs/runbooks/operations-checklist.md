## 실제 경고 연결

기존 operations_monitor에 operational_checks를 연결했다. JSON 상태/시각만 읽고 백업·원장·관측 실패/오래됨, 월간 복구 기한을 확인한다. Java Instant 나노초를 노트북 Python3.10의 마이크로초로 정규화한다. 정상 서버 시각을 미관측으로 오분류하지 않는다. 최신 관측 실패가 마지막 PASS보다 새로우면 즉시 경고다.

기존 phone-notify의 OperationsWarning 고정 문구와 현재 ntfy 설정을 사용한다. 비밀·콘텐츠·원시 오류는 넣지 않는다. 같은 문제 집합의 경고를 중복 보내지 않으며 정상 회복 후 새 발생 때 다시 알린다. 실패/불명확 전송도 자동 중복하지 않는다. 비용은 기존 전용 알림을 유지한다. 폰 서버 접수는 실제 수신 확인이 아니다. 수신자는 현재 대화에 ‘운영 점검 오류 확인’이라고 알려주면 AI가 보호 기록·실제 프로세스부터 확인하고 해결 가능한 부분을 먼저 처리한다. 새 키 입력을 선제 요구하지 않는다.

감시는 현재 Windows 사용자·노트북 실행과 Docker에 의존한다. 절전/종료 중 감시나 자동 복구를 보장하지 않는다. 재개는 validation_runtime connect의 기존 관측 감시 시작을 재사용하며 중복 프로세스는 기존 파일 잠금으로 차단한다. 비용·백업·원장·관측 프로세스와 실제 조회 시각을 함께 확인한다.
