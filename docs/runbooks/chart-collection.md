# 실제 인기 차트 수집 운영

P16-08 베타 후속 / D12·R090 / 2026-10-19. 제공자 조건 확인 유예는 사용자의 무료 서비스 진행 판단이며 제공자 허가 확보라고 기록하지 않는다. 현재 베타의 실제 수집 연결 누락을 보완한다.

## 연결과 활성화

API 요청은 기존 게시본만 조회한다. 실제 수집은 `LiveChartCollectionConfiguration`의 staging/prod 전용 설정에서 `songrecord.charts.live-enabled=true`와 `songrecord.charts.storage-approved=true`를 모두 명시한 경우에만 연결된다. 일반 fixture=false 호출은 여전히 거절한다. fixture 개발 설정은 유지하며 운영 활성화에 fixture=true를 사용하지 않는다.

주기 작업은 `songrecord.charts.scheduling-enabled=true`까지 필요하다. 기존 experiment에서는 관리자 전용 `chart-policy.json`을 `scope=experiment.charts:v1`, enabled/storage_approved=true, interval_seconds=21600으로 명시한다. runtime은 worker에만 활성화 값을 넣고 api에는 비활성 값을 넣는다. 파일 없으면 모두 비활성이다. 키 집합/형식/300~86400초 경계·저장 미허용 시 활성화 거절을 검증한다.

서버 시작 후5초, 한 차례6개조합 완료 후6시간의 고정 지연이다. TJ/KY와 DAILY/WEEKLY/MONTHLY를 독립 처리하며 한 범위 실패로 다른 범위를 건너뛰지 않는다. 이 간격은 운영자의 수집 정책이며 제공자 자료 갱신 주기/정확 집계 시작·종료 시각을 보장하지 않는다.

## 기존 보호 유지

- 기존 총30초 예산·동시 요청 최대2·네트워크/시간초과 자동재시도1·2MiB 상한과 트랜잭션 밖 원본 수집을 유지한다.
- 브랜드/기간/출처·전체 배열·필수값·번호 중복·배열 순서를 검증한 후 원자적으로 게시한다. 동일 데이터인 기간을 조작하지 않고 100곡으로 하드코딩하지 않는다.
- 실패/빈 배열/손상은 이전 같은 범위의 게시본을 보존하고 stale와 원래 수집시각을 표시한다. 게시본이 없으면 기존503을 유지한다. 개인 변경 로그에 공용 차트를 넣지 않는다.
- 개인정보·기존 녹음/계정·인증·업로드 잠금·삭제·비용/보관 정책은 변경하지 않는다. 이번에 기존 차트 이력 자동 삭제를 새로 활성화하지 않는다. 수집 이력의 용량 증가는 운영 점검 대상으로 보존한다.

## 배포와 확인 순서

1. 기본 비활성 상태의 구현/실제 일회용MySQL/전체 서버/도구/빌드·소스지문·별도 현재모델 검토를 확인한다.
2. 기존 AWS experiment에 대한 정확한 배포 승인을 받은 뒤, 현재 이미지/compose/runtime/프록시 지문·진행job/삭제대기0·업로드잠금1을 재대조한다.
3. 새 JAR와 runtime, 위 chart-policy만 적용하며 API/worker를 잠시 재시작한다. DB 컨테이너·기존 계정·녹음·사용량/예약·업로드잠금·인증/R2키/웹·작업자/관측정책·네트워크 범위는 보존한다.
4. 6개 범위 게시와 항목 수/수집시각·revision을 확인하고 폰의 TJ/KY 일간·주간·월간을 확인한다. 외부 응답200만으로 서버 게시/폰 표시 통과라고 쓰지 않는다.
5. 실제 소스/배포/실기·커밋·필수CI를 연결한다. 실패 시 이전 이미지/compose/runtime/수집 비활성으로 복원하되 DB나 생긴 공용 차트 행을 지워 실패를 숨기지 않는다.

2026-10-19 USER172 승인 후 기존 실험 서버에 반영했고, 6개 범위가 각각100곡/revision1로 게시됐다. 작업자만6시간마다 갱신하며 폰 표시·커밋·CI의 최종 결과는 [P16-08 후속 검증](../verification/P16-08-charts.md)을 따른다. 새 스키마·일반 공개 웹 게시·유료 서비스·추가 계정/키 발급은 포함하지 않는다.
