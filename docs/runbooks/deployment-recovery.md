# P24-08 배포·마이그레이션·복구 절차

근거: 계획 p01057–01058, R127, P24-05–07. 아래는 실행 준비 절차이며 공개 운영 배포 승인이 아니다.

## 배포 전 중단 조건과 백업

1. 현재 정상 SHA·이미지 digest·DB Flyway 버전/체크섬·앱 지원 범위·기존 업로드 잠금 값을 비밀값 없이 기록한다. 운영 배포와 검증 환경을 구분한다.
2. 운영 DB 전용 관리 연결에서 `global_storage_usage.id=1`의 `upload_locked=TRUE`와 revision 증가를 한 트랜잭션으로 적용한다. 새 예약의 `UPLOAD_BUDGET_LOCKED`를 확인한다. 기존 멱등 재시도는 예약을 추가하지 않고 원래 결과를 돌려줄 수 있다.
3. 이 플래그는 전체 쓰기 중지 기능이 아니다. 기존 시도의 URL 재발급·이미 발급한 R2 URL·동기화 쓰기는 별도로 통제해야 한다. 게이트웨이에서 변경 요청을 유지보수 응답으로 막고 진행 중 DB 트랜잭션·작업 lease를 배출한 뒤 stateless API/작업자를 정지한다. 이미 발급한 URL은 최대 10분의 남은 유효기간이 끝나야 하며 R2 임시 객체 대조를 완료한다. DB나 R2 원본을 삭제하지 않는다.
4. P24-05 암호화 백업·파일 목록·체크섬과 P24-06 독립 삭제 원장의 인증된 읽기 검사를 실행한다. 현재 일일 실행기는 같은 UTC 날짜의 복구 지점을 재사용한다. 따라서 실행 PASS를 방금 생성한 배포 직전 스냅샷으로 간주하지 않는다. 백업 시점 이후 변경이 있으면 새 배포 직전 복구 지점 지원을 준비해 검증하기 전까지 운영 배포를 막는다. 일일 지점으로 검증 환경을 재시작하는 경우 정확한 시점과 허용 손실 범위를 기록한다.
5. P24-07 절차로 별도 DB에 복구 가능한지 확인한다. 백업·원장·복구 검사 실패, 원장 동시 변경, 호환성 미확인은 잠금 유지·배포 중단·폰 알림 사유다.

## 구버전 앱과 전진 마이그레이션

- 지원할 실제 앱 빌드/SHA를 지정한다. 같은 `/v1` 요청·응답 필드, 오류 코드, UUID·계정 격리, 멱등 재시도, 증분 수신과 만료 후 전체 수신, 기존 업로드 재개를 대조한다. 새로운 필드를 무시하는지와 기존 필수 필드/enum이 유지되는지 검사한다. 서버 health만으로 앱 호환을 판정하지 않는다.
- 컬럼·제약 변경은 추가 → 구/신 코드 공존 → 데이터 전진 보정 → 후속 제거 순서로 한다. 현재 적용된 Flyway 파일의 체크섬을 바꾸거나 DB 역마이그레이션을 실행하지 않는다. 데이터 보정은 별도 새 버전에서 범위·재실행·보존 조건을 검증한다.
- 이전 서버 이미지가 현재 스키마의 Flyway 검증·JPA validate·기존 계약을 통과하는지 별도 검증한다. 통과하지 않으면 이전 이미지로 강제 시작하지 않고 전진 수정한다. `repair`로 체크섬 문제를 감추지 않는다.

## 서버 이미지 되돌리기

- 정상 이미지 digest를 보존한다. 검증 환경은 `VALIDATION_IMAGE_TAG`에 확인된 이전 P24 태그를 지정해 `tools/validation_runtime.py connect`로 API/작업자만 재생성한다. DB 볼륨·기존 암호·서명 키·R2 파일을 그대로 유지한다. 운영은 해당 환경의 승인된 배포 도구로 같은 경계를 적용한다.
- 이전 이미지가 신 스키마와 호환되는 경우에만 서버 바이너리를 되돌린다. DB 스키마는 현재 버전을 유지한다. 새 삭제 원장/백업 안전장치를 제거하는 이전 버전은 되돌리기 후보에서 제외한다.
- 실패하면 변경 요청 차단을 유지하고 새 이미지 전진 수정 또는 P24-07의 별도 복원 환경을 준비한다. 원본 DB 덮어쓰기·볼륨 삭제·R2 일괄 삭제로 복구하지 않는다.

## 재개와 기록

TLS·인증·구버전 계약·동기화·예약/재발급·파일/원장·비용 관측을 검증한다. 기존 비용/대조 잠금은 해제하지 않는다. 업로드 잠금도 배포 전 값과 현재 원인을 대조한 뒤 이번 유지보수 잠금만 해제한다. 원래 잠겼거나 다른 담당자가 변경했으면 유지한다. 승인된 변경 요청 게이트를 열고 시각·SHA/digest·스키마·검사·RPO/RTO·남은 출시 조건을 기록한다. 공개 도메인/실제 OAuth/구버전 출시 설치본이 없는 현재 노트북 검증은 운영 출시 통과로 확대하지 않는다.
