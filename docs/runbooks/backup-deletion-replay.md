# 백업 삭제 원장과 복원 차단

P24-06은 기록 UUID 삭제와 서버 파일 세대 삭제를 구분한다. 확정 삭제된 사용자·녹음·세대를 오래된 DB와 파일 사본으로 되살리지 않도록 백업 스냅샷 밖의 암호화 원장을 유지한다. 실제 서비스 복원·재생·RPO/RTO 측정은 P24-07에서 수행한다.

## 실제 삭제 전 확인

staging/prod에서 R2 저장이 활성화되면 `BackupDeletionFence`가 필수다. 삭제 요청은 DB `operational_backup_fence`에 서버 UUID·세대·상태·revision만 남긴다. 별도 백업 프로세스가 백업 키로 원격 원장을 암호화 저장하고 실제 다시 읽기까지 확인해야 동일 revision을 승인한다. 앱·작업자에는 백업 키나 암호화 키를 주입하지 않는다.

확인 대기는 `Awaiting`으로 분리해 작업을 5초 뒤 재예약한다. 코드/외부 삭제 실패 예산을 소비하지 않으며 원격 확인 전에는 R2 DELETE가 전송되지 않는다. 녹음 영구 삭제는 UUID, 서버 사본 정리는 해당 UUID의 generation, 계정 삭제는 소유자 전체에 적용한다. 권한·lease·현재 보호 조건과 객체 부재 확인은 기존 순서를 유지한다.

아직 삭제하지 않은 사본이 보호 대상이 되면 취소 revision을 원격에 반영한다. 실제 확정 삭제 원장은 이후의 취소나 복원된 옛 DB 값으로 되돌리지 않는다. 조회할 수 없는 원장·revision 충돌·서명/암호화 실패는 복원 허용 근거가 아니다.

## 게시와 정리

DB 백업과 원장 정리는 같은 OS 파일 잠금을 사용한다. 살아 있는 DELETING 계정이 있으면 새 DB 백업을 게시하지 않는다. 삭제 대상의 개인정보가 새 일일 백업으로 계속 연장되는 것을 막고, 서비스 데이터 제거 후 다음 백업을 재시도한다.

새 매니페스트에는 같은 DB 잠금에서 읽은 전체 소유자 목록을 넣는다. 이전 지점의 소유자 목록이 없으면 계정 백업 부재를 추정하지 않는다. 복사 전에 암호화 파일 인벤토리를 저장해 중단된 사본도 식별한다. 정상 카탈로그 밖의 객체도 실제 R2 목록으로 확인하며, 미분류 사본이 남으면 계정의 백업 제거를 완료 처리하지 않는다.

7일 지난 DB 지점과 확정 삭제 사본을 전용 백업 경로에서 정리하고 실제 부재를 확인한다. 활성 파일과 다른 계정 사본은 유지한다. 중단된 정리 원장을 먼저 재개하며, 잘못된 목록을 비어 있는 것으로 취급하지 않는다. 개인 데이터 제거·백업 부재 확인·30일 경과가 모두 입증되고 원래 계정 삭제 제어 작업도 종료된 소유자만 최소 원장을 정리한다. 미완료 항목은 30일이라는 이유만으로 숨기지 않는다.

원장 감시는 평상시 30초, 새 확인 대기는 5초 간격으로 DB 변경을 확인한다. 원격 쓰기는 변경이 있을 때만 하고 정리·전체 목록 검사는 시간 기준으로 재확인한다. AI를 호출하지 않는다. 노트북 종료·절전·통신 실패 중에는 기한을 보장하지 않으며, 지연·미완료는 운영 경고 대상이다. 운영 알림 연결은 P24-10에서 확인한다.

## 복원 전에 적용

`backup_overlay.py`는 `song_record_restore_<UUID32>` 형태의 새 일회용 DB만 대상으로 한다. 검토하지 않은 소유자 테이블과 FK 순환은 거절한다. 기존 검증/개발/운영 DB에는 실행하지 않는다.

사용자 삭제는 검토된 FK 순서로 그 소유자 데이터만 제거한다. 녹음 UUID 삭제는 해당 기록을 제거하고, 파일 generation 삭제는 그 세대의 클라우드 사본만 비운다. 같은 녹음의 새 세대와 다른 계정 데이터는 유지한다. 확정 원장을 복원 DB에 다시 넣고 실제 남은 자산 기준으로 사용량을 대조한다. 고정 컨디션과 역사 기록은 임의로 재작성하지 않는다. 다른 계정의 복구 사본이나 원래 서버 DB를 지우는 절차가 아니다.

복원할 파일은 독립 원장을 인증해서 읽고 걸러낸 목록만 사용한다. 원장 원문·녹음·토큰·서명 URL을 보고서에 넣지 않는다. 원격 원장과 파일 검사·DB 적용이 모두 끝나기 전에 복원된 서버를 공개하거나 삭제 작업자를 켜지 않는다.

현재 연결은 노트북의 분리 검증 환경이다. 운영 계정·외부 서버·운영 키로 자동 확장하지 않는다. 계정 삭제 작업자와 기존 유지보수 스케줄은 기본 비활성 상태를 유지하며 실제 운영 활성화는 별도 배포 확인 대상이다.
