# 운영 관측과 감사 — P24-04

원본 계획 p01044~p01046, 설계14.2/14.3, R120/R124의 서버 관측 기반을 연결한다. 원음·메모·요청/응답 본문·인증/lease 토큰·전체 서명 URL·객체 키·검색어를 관측 테이블이나 지표 요약에 넣지 않는다.

## 수집 범위와 해석

- staging/prod의 `/v1/` 요청: 고정 작업 종류, 성공/실패/한도 결과, HTTP 상태, 서버 처리 시간, 검증된 AccountAccess 세션의 계정 UUID, 경로 또는 검증된 고정 대상 UUID. 계정 권한을 새로 부여하는 기능이 아니다. `ANONYMOUS`는 이 세션 관측에서 계정 UUID를 확보하지 못한 행이며, 웹 소유권 증명 등 다른 경로의 비인증 판정을 대신하지 않는다.
- 동기화는 요청 처리 시간·실패와 서버 head/client after 사이의 미수신 변경 개수를 기록한다. 이는 서버가 본 변화량이며 기기의 실제 적용 완료나 전체 오프라인 대기 시간을 보장하지 않는다. 커서나 변경 payload는 기록하지 않는다.
- 작업은 실제 트랜잭션 커밋 뒤 claim/renew/success/retry/failure를 기록한다. JVM 작업자 UUID·job UUID·대상 UUID·시도·시각만 남긴다. lease 토큰·작업 payload·외부 예외 문자열은 전달하지 않는다. 롤백되거나 만료된 시도의 성공은 남지 않는다.
- 영구 삭제 원장 삽입과 확정 고정 교체는 DB 트리거로 같은 트랜잭션에 감사 행을 남긴다. 교체의 이전/새 녹음 UUID, 요청 권한의 소유 계정 UUID·시각·결과를 기록한다. 요청 수락과 실제 교체 확정은 `PIN_REPLACE`/`PIN_REPLACE_COMMITTED`로 구분한다. 실행 작업자 식별은 작업 수명 감사와 대조한다.
- 고정10칸 점유는 같은 DB 상태의 `PIN_SLOTS_TEN`으로 기록하고, 저장 완료와 대기 슬롯은 별도 집계한다. 대기 슬롯을 보관 완료로 세지 않는다.
- 30일 서버 관측 활성 계정·같은 기간 고정10 도달·PIN_LIMIT/QUOTA 경험·보관 요청·서로 다른 두 녹음 저장을 고유 계정과 고유 대상 기준으로 계산한다. 반복 HTTP 호출이나 같은 녹음 저장 재조회는 고유 계정/두 번째 저장 수를 늘리지 않는다.
- **현재 클라이언트 실제 재생·오프라인 방문 신호는 연결되지 않았다.** 재생 URL 발급은 실제 재생이 아니다. 실제 재생 지표는 `null/NOT_CONNECTED`, 활성 계정은 `server_observed`로 표시한다. R124 전체 사용자/재사용 판정은 P25-07 앱 통합·실제 신호 검증까지 남기며 현재 숫자로 전체 베타 수요를 단정하지 않는다.

## 조회·보호

`python tools/operations_monitor.py once`는 검증 컨테이너의 비공개 `OperationsOperator`를 실행해 집계만 읽는다. 공개 관리자/메트릭 API는 없다. 작업 대기/시도/만료 lease, 글로벌 용량/임시/확정/대조 오류·최종 시각, 차트별 수집·게시 시각, 삭제 원장/계정 삭제 대기와 실패를 따로 표시한다. null 시각·빈 차트 범위는 수집 미확인이며 건강 판정이 아니다. 이전 DB·운영 DB에 자동 연결하지 않는다.

새 관측 행은 최소 UUID/종류/시각만 포함한다. 기존 데이터·원장 보관 규칙은 변경하지 않는다. 관측·감사 실제 보관 및 운영 정리 범위는 P24-09 개인정보 표시와 P24-10 운영 점검에서 대조하며 아직 적용하지 않은 보관 상한을 보장하지 않는다.

로그의 client request ID는 공개 응답/오류 계약대로 유지하되 MDC에는 `sha256:<SHA-256 UTF-8 hex>`만 넣는다. 합법 문자로 된 인증값이 잘못 request ID에 입력되어도 원문을 로그에 남기지 않는다. 비표준 HTTP method도 `OTHER`로만 기록한다. 응답 요청 ID를 해시하면 로그 상관값을 찾고, 관측 로그의 event UUID로 DB 감사 행을 찾을 수 있다.

검증 API/worker Docker 로그는 각각10MiB×3개로 제한한다. 로그 원문은 읽기 프로그램 메모리에서만 검사하고, 고정 관측 실패 표식 개수만 요약한다. 잘린 로그는 실패0으로 보지 않는다. 요약은 Git 제외 `.local/workflow/operations/latest.json`, 실패는 `failure.json`이다. 이 로그 제한은 DB 감사 행의 보관 상한을 뜻하지 않는다.

P24-04 이상 검증 이미지의 `validation_runtime.py connect`는 숨겨진 단일 `operations_monitor.py watch`를 요청한다. 60초마다 집계하며 파일 잠금으로 중복 실행을 막는다. AI 호출 없음. 절전·노트북 종료 중에는 실행을 보장하지 않는다. 경고/정기 운영 대응 연결은 P24-10에서 확인한다. 관측 쓰기 실패는 고정 오류 코드로 드러내고, HTTP 계측 실패로 이미 성공한 사용자 변경을 되돌리지 않는다. 확정 삭제/교체의 DB 감사는 해당 변경과 함께 원자적으로 성공해야 한다.
