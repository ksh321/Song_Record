# R2 비용 감시 — P24-03

요구사항 R121/R122, 원본 설계 p01093~p01099와 계획 P24-03을 따른다. 목표 10만원은 청구 상한이 아니다. 5만원 알림·6만원 경고·7만원 신규 업로드 예약 잠금은 **R2 예상 월 비용** 기준이다. 기존 정보 저장·로컬 녹음·재생·삭제·내보내기·고정 해제는 잠금 경로를 추가하지 않는다. 기존 진행 중 예약의 재조회도 보존한다.

## 자료와 추정 경계

- 계정 한정 Account Analytics Read 토큰을 최초 한 번 Windows 사용자 DPAPI로 등록한다. 실제 인증·R2 관리 조회403·암호화 후 자동 분석 조회가 통과해야 등록 완료다. 토큰은 argv/환경변수/로그/Git에 쓰지 않는다. 만료·조회 실패를 가짜 비용0으로 바꾸지 않는다.
- Cloudflare 계정 전체 R2 요청과 저장 집계를 읽는다. Standard임을 확인한 기존 dev/prod 및 검증 staging-dev 6개 버킷을 등록한다. 새 버킷/다른 저장 클래스는 확인 후 등록해야 하며 미등록 범위는 차단한다. 임시·확정·등록된 백업 바이트 모두 비용에 포함한다. 개인 용량 제외 규칙과 운영비 제외 규칙을 혼동하지 않는다.
- R2 화면에서 확인한 청구 주기는 매월8일이다. 조회는 이 시작일부터 현재까지이며 경계 시각은 UTC 가정으로 명시한다. 무료 분량을 계정 전체에 한 번만 적용한다. 요청 단위 올림·저장 GB-month 단위 올림을 반영한다.
- 저장은 제공자 시간별 표본의 일일 최고치 기반이다. 향후 저장은 버킷별 관측 최고치가 유지되고, 요청은 이번 주기의 평균 속도가 유지된다고 가정한다. 향후 급증이나 관측 사이 최고치는 보장하지 않는다. 청구서 실측 금액은 별도이며 현재 미확인이다.
- 공개 요금표에 없는 `GetBucketSippyConfiguration` / `GetBucketNotificationConfiguration`은 확정 A/B 실적에 합치지 않는다. 별도 개수를 보존하고 현재 Standard의 더 높은 A 요율로 보수적 예산 추정을 한다. 실제 청구 분류는 미확인이다. 그 밖의 새 미분류 작업은 계산 실패로 처리한다.
- 환율은 ECB 공개 USD/EUR·KRW/EUR의 기준일을 보존해 교차 환산한다. 7일 초과·조회 실패·이상값은 미확인이다. 카드 결제 환율·세금은 별도이며 추정액에 포함됐다고 표시하지 않는다.
- 로컬 검증 환경 서버/MySQL/감시: 추가 유료 서비스 없음. 운영 백업은 P24-05에서 연결할 때 실제 대상·비용을 추가한다. 운영 서버·DB·백업·모니터링 서비스 요금·세금·결제 환율은 운영 선택/청구서에 따라 별도로 기록한다. 모르는 값을0원으로 표시하지 않는다.
- 기준: [Cloudflare R2 요금](https://developers.cloudflare.com/r2/pricing/), [R2 분석 자료](https://developers.cloudflare.com/r2/platform/metrics-analytics/), [ECB 기준 환율](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html). 각 실행에서 Cloudflare 공식 문서 저장소 원본의 단가·무료 한도·요청 분류를 대조하고 해시/시각을 남긴다. 불일치·조회 실패면 새 정상 비용으로 반영하지 않는다. 요율을 자동 결제 승인으로 사용하지 않는다.

## 연결과 잠금

`python tools/cost_monitor.py once`가 제공자 조회 → 원화 예상 → 비공개 검증 DB 반영 → 필요한 폰 알림을 실행한다. 공개 비용 관리자 API는 없다. 운영자가 검증 컨테이너의 private operator를 사용하며 DB 비밀번호는 tmpfs에서만 읽는다. 이번 도구는 검증 DB 전용이며 운영 DB에 자동 적용하지 않는다.

`validation_runtime.py connect`는 정상 TLS 상태를 확인한 뒤 `cost_monitor.py watch`를 숨겨진 단일 백그라운드 프로세스로 요청한다. 파일 잠금으로 중복 감시를 막고 매시간 조회해 일일 대조보다 자주 갱신한다. AI 호출은 없다. 노트북 종료·절전 중에는 실행을 보장하지 않으며 다음 연결 때 재개한다.

서버는 staging/prod 요청 접수 전 `cost_monitor_required`를 켠다. 신규 예약은 `cost_upload_locked` 및 관측 최신성을 확인한다. 관측 없음·26시간 초과·미래 시각 이상은 신규 예약을 막는다. 새 정상 관측만 비용 잠금을 갱신하며 이전0원 결과로 되돌릴 수 없다. 수동 `upload_locked`·대조 `reconciliation_locked`는 이 도구가 해제하지 않는다. 26시간은 일일 감시의 지연 허용 경계이며 새 구현값으로 기록한다.

## 근거와 알림

비밀값 없는 요약은 Git 제외 `.local/workflow/cost/latest.json`, 오류는 `failure.json`, 감시 PID는 `process.json`에 둔다. 최근 정상 결과는 오류로 덮어쓰지 않는다. 서버 반영이 실패하면 비용 보고를 정상으로 만들지 않는다.

기존 `phone-notify.ps1`의 고정 CostNotice/CostWarning/CostLock/CostUnknown 문구를 사용한다. 한 청구 주기·단계당 한 번이며 오류는 날짜당 한 번이다. 전송 시도 원장을 먼저 기록하고 결과 미확인 때 자동 재전송하지 않는다. 서버 접수는 휴대폰 수신 확인과 다르다. 오류 시 키를 다시 입력하게 하지 않고 저장된 비밀값 없는 진단부터 AI가 조사한다.

감시 실패 때 기존 R2 저장·읽기 과금은 계속 발생한다. 업로드 잠금·알림·단일 노트북 감시는 절대 비용 상한이나 무중단 서비스를 보장하지 않는다.
