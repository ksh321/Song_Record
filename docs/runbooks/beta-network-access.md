# 베타 앱의 네트워크 접속 범위

2026-10-19 / P25-06 완료 후 사용자 유지보수 요청. 사용자는 같은 Wi-Fi에서는 로그인 성공·모바일 데이터에서는 연결 실패를 확인하고 어디서든 앱 접속을 요청했다. USER170의 실제 저장 직전 구체 허용 회신(dd/ㅇㅇ)을 확인했다.

## 적용 정책

- 기존 AWS experiment 보안 그룹에 TCP443/IPv4 `0.0.0.0/0` 규칙1개만 추가. 기존4개 규칙·SSH 관리주소 제한·내부 API/DB 포트 비공개·HTTP ACME 전용 경로는 유지한다. IPv6 공인 주소/추가 리스너는 만들지 않았다.
- 기존 IP HTTPS 기본 가상호스트에서 앱 `/v1/` 요청의 출발지 주소 제한을 해제한다. 로그인에는 기존 제공자 증명·서버 계정/세션·소유권 검사가 필요하며 사용자 데이터 조회 권한을 우회하지 않는다.
- 같은 호스트의 `/v1/account/web/`와 기타 웹 경로, 별도 도메인 개인정보 초안/웹 탈퇴 화면은 기존 허용주소 제한을 유지한다. 앱 API 접속 확대는 웹 초안·일반 공개 정책 게시 승인이 아니다.
- TLS1.2/1.3·상위 서버 인증서 검증·요청량10r/s/burst20·본문1MiB·시간 제한을 보존한다. 서버 베타 계정/저장/비용·대조 제한과 신규 업로드 수동잠금은 유지한다. 공개 접근은 인터넷에서 로그인 시도를 가능하게 하므로 운영 감시도 유지한다.

## 실제 적용과 확인

원래 nginx SHA256 `6740259fba95ec5305b46f2a536d40d95da075e95a76ecd8b1ab67acc5a1f285` → 새 `04e6014610034bfa64035770568c32da1d6b7a26f17279c8f8e5b38748517c8f`. 기존 도메인 서버 블록은 바이트 그대로 보존하고 IP 서버의 앱/웹 경로만 분리했다. 실제 nginx 후보/적용 문법검사·proxy reload PASS. 서비스 API/worker/DB 재시작·JAR/앱 수정·키 발급·데이터 삭제 없음.

## 재시작·갱신·복원

서버의 실제 `/opt/song-record-experiment/https/nginx.conf`와 기존 볼륨을 유지한다. 인증서 갱신은 현재 설정 문법검사/재로드이며 예전 2주소 제한 템플릿으로 덮어쓰지 않는다. 재구축 때는 이 앱/웹 분리 정책과 보안 그룹 범위를 다시 대조한다. IP가 바뀌면 인증서·앱주소·DNS/관리 접근을 함께 확인한다. 원래 설정 사본과 배포별 지문은 Git 제외 로컬/서버에 보존한다.

되돌리기는 원래 nginx 사본·문법검사·재로드와 이번 추가443 규칙만 대상으로 한다. 기존 SSH·ACME·다른 규칙을 지우지 않는다. 실제 클라우드 권한 변경의 실행시점 확인과 현재 사용자 권한을 따른다. 토큰·계정 식별자·원음·원본 주소/전체 환경변수를 문서에 넣지 않는다.
