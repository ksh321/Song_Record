# 검증 백업 실제 복구 훈련

P24-07은 인증 암호화 백업을 새 격리 DB와 제한된 전용 계정으로 복원하고, 원장·파일 목록·체크섬·음성 재생을 확인한다. 원래 검증 DB·R2 파일·삭제 스케줄을 바꾸지 않는다. 공개 서비스 로그인과 운영 서버 전환은 별도 배포 검증이다.

## 실행

AI가 설치된 의존성 Python에서 `tools/backup_restore.py run`을 직접 실행한다. 등록된 Windows 암호화 백업 키를 자동 사용한다. 원격 카탈로그·DB 해시·파일 인증과 독립 삭제 원장을 먼저 확인하고, 새 `song_record_restore_<UUID32>` DB와 그 DB에만 권한이 있는 `sr_restore_<UUID16>` 계정을 만든다. 기존 이름 충돌은 재사용/초기화하지 않고 실패한다.

원본 덤프의 관리자 definer는 조건부 DDL/CREATE 문장에서만 현재 복원 계정으로 바꾼다. INSERT 안의 사용자 메모는 그대로 보존한다. 복원 계정에 원래 서버 DB 권한이나 전역 관리자 권한을 추가하지 않는다. 현재 JAR의 Flyway 마이그레이션으로 전진 적용하고, 기본 테이블만 소유자/FK 검사에 사용한다. 집계 뷰를 삭제 테이블로 분류하거나 미검토 테이블을 임의 허용하지 않는다.

삭제 원장을 새 복원 DB에 적용한 뒤 실제 클라우드 자산 목록이 백업 목록에서 삭제된 항목을 제외한 결과와 일치해야 한다. 각 사본을 복호화해 크기/SHA-256과 음성 길이·전체 디코딩을 확인한다. 이번에 생성한 시험 음성만 노트북 재생을 시험한다. 프로그램의 재생 완료와 사람이 소리를 들었다는 확인은 구분한다. 음성 평문 시험 파일은 검사 뒤 제거한다.

긴 복원 후 원장을 다시 읽어 새로운 삭제가 생겼으면 공개하지 않고 재시도를 요구한다. 검사 완료 전에는 복원 서버를 공개하거나 삭제/업로드 스케줄을 켜지 않는다. 원본 파일을 덮어쓰는 작업은 없다.

## 측정과 기록

- RPO는 복구 검사 시작과 선택 지점의 기록 시각 차이다. 실제 손실된 개별 변경을 전부 확인한 수치가 아니라 해당 지점 이후의 잠재 손실 시간 범위다.
- 데이터 복구 RTO는 단일 실행에서 백업 확인·새 DB 생성·가져오기·전진 마이그레이션·원장·파일 대조·음성 검사를 끝낸 시간이다. 첫 시도부터 오류 해결과 재시도까지의 전체 경과 시간은 별도로 기록한다. 처음 기록한 DB 생성 시각만 남았으면 그 기준과 정확한 첫 시작 미기록을 명시한다.
- 24시간은 목표다. 공개 서비스/실제 OAuth 세션 복구·운영 인프라 전환을 시험하지 않은 경우 전체 서비스 RTO로 표시하지 않는다. 한 번의 검증 결과를 미래 보장으로 안내하지 않는다.
- `.local/workflow/restore/<run>/report.json`, 암호화된 제한 계정 정보, scope.json을 보존한다. 원문 DB·음성·암호·토큰을 보고서/대화/Git에 넣지 않는다. 실패는 단계와 고정 오류 코드만 남긴다.

실패한 새 DB는 원래 DB와 분리해 조사용으로 보존한다. 정리할 때는 생성 기록의 disposable 표식·정확한 이름·전용 사용자·범위를 대조하고 이 환경만 처리한다. 원래 DB 초기화·볼륨 삭제·일괄 R2 삭제·DB 역마이그레이션 절차는 없다. 월간 반복/실패 알림 등록은 P24-10의 범위다.
