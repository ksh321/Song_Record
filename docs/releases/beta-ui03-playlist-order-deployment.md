# UI03 플레이리스트 순서·다른 기기 수신 보완

USER-184는 목록 순서를 다른 기기에도 유지하도록 구현하는 승인이다. 아래 실제 서버 적용과 베타 설치는 별도 확인 전에는 실행하지 않는다.

## 변경 범위

- V35는 `playlist.display_order` 열과 음수 방지 제약만 추가한다. 기존 행은 0이며 기존 UUID 순서를 유지한다. 곡·녹음·목록 관계를 지우거나 재작성하지 않는다.
- 활성 목록 전체의 revision을 확인해 순서를 한 트랜잭션으로 저장한다. 변경 피드와 전체 사본으로 다른 기기에 전달하며, 다른 기기의 선행 수정과 충돌하면 전체 거절한다. 기존 곡 순서 API와 구분한다.
- 앱은 로컬 DB14에 순서 충돌의 사용자 결정 기록을 보관한다. 기존 요청/응답/재시도 이력은 남기고, 명시적으로 포기한 순서가 이후 수신을 막지 않게 한다. 기존 로컬 데이터와 파일을 초기화하지 않는다.
- 최초 전체 사본에서 하트·플리 아이콘·목록 순서가 빠지던 화면 변환을 보완한다. 목록 곡명 미리보기·곡수, 길게 누른 뒤 순서 이동, 저장 대기/충돌 안내, 양테마 공통 강조색 전경을 포함한다.
- 실제 원격 파형은 검증된 한 번의 메모리 수신 데이터를 재생과 공유한다. 별도 파일 다운로드/업로드 해제는 하지 않는다. 합성 음원으로 native 재생·파형 일치를 확인한 근거는 P25-04 검증 기록에 있다.

## 적용 전후 보호

스키마34·현재 이미지/설정 해시·세 서비스 healthy·작업/삭제 대기0·업로드 잠금·26시간 이내 암호화 백업을 실행 직전 다시 확인한다. API와 작업자만 재시작하며 DB 컨테이너·볼륨을 재생성하지 않는다.

계정·곡·플리·녹음 수, 용량/예약량/업로드 잠금, 키·하트·아이콘·컨디션 정의·녹음 당시 이름/이력의 전후 지문을 내부 대조한다. 공개 로그에는 개인 메타데이터나 비밀값을 쓰지 않는다. 새 열의 기존 행 값이 모두0인지 확인한다.

실패 시 기존 compose와 이미지로 복귀한다. V35 열을 삭제하거나 DB 백업 복원을 자동 실행하지 않는다. 서버 성공 후에만 같은 패키지/서명의 APK를 `install -r`로 업데이트한다. 기존 앱 삭제와 데이터 초기화는 금지한다.

폰에서는 기존 로그인·하트·키·플리·컨디션 보존, 공통 UI와 순서 이동을 확인한다. 순서 실기는 이름이 명확한 빈 시험 목록2개로 저장/재실행/서버 읽기 대조 후 그 시험 목록만 정리하는 범위를 승인에 포함한다. 개인 목록과 곡은 삭제하지 않는다. 다른 실제 기기는 사용 가능 여부가 미확인이며, 별도 기기 실기로 과장하지 않고 사본/피드 수신 테스트와 구분한다.
