# UI03 휴지통 곡의 플리 후보·곡만 복원

USER-187 선택은 구현 범위 확인이다. 실제 AWS 반영과 베타 설치는 검증 후 별도 운영 배포 승인 대상이다.

## 동작과 보존

- 휴지통 곡도 검색·차트에서 플리에 먼저 담을 수 있다. 이때 내 곡이나 녹음은 복원하지 않는다.
- 그 후보의 ‘내 곡 등록’은 ‘곡만 복원’ 확인창을 연다. 취소하면 변경하지 않는다. 확인하면 곡만 복원하며 함께 삭제했던 녹음은 휴지통에 남긴다.
- 새 후보의 항목 ID·순서를 유지해 복원 곡에 연결한다. 같은 목록의 과거 숨긴 항목은 중복 복원하지 않고 삭제 이력으로 보존한다. 이미 활성인 분리 녹음의 기존 SONG_ONLY 연결 revision 보호는 유지한다.
- V36은 숨긴 항목을 제외한 두 생성 열과 중복 방지 인덱스를 추가하고 종전 전체 항목 중복 인덱스를 교체한다. 기존 행·삭제 이력·파일을 삭제하지 않는다. 활성 곡의 중복과 계정 간 접근은 계속 차단한다.
- 앱 최초 사본·변경분 수신은 숨긴 이력과 새 후보가 공존해도 보존하며 활성 중복은 거절한다. 미확인 복원은 기존 휴지통 재시도 기록을 사용한다.

## 실행 전후 조건

실행 직전 스키마35, 기존 이미지/설정 해시, DB·API·작업자 healthy, 작업·개인 삭제 대기0, 업로드 잠금, 26시간 이내 암호화 백업을 확인한다. API·작업자만 잠시 재시작하며 DB 컨테이너/볼륨은 유지한다. 곡·녹음·플리·항목·순서·키·하트·아이콘·컨디션·이력·용량의 전후 지문을 대조하고 새 생성 열이 기존 데이터와 일치하는지 확인한다.

실패하면 기존 compose/이미지로 복귀하며 스키마 열 삭제나 DB 백업 복원은 자동 실행하지 않는다. V36 이후 새 후보 데이터가 생긴 상태의 장기 롤백은 별도 검토한다. 서버 성공 후 동일 서명/패키지의 베타만 `install -r`로 교체한다. 앱 삭제/데이터 초기화·업로드 잠금 해제·결제/네트워크 변경은 포함하지 않는다.

개인 곡·녹음을 휴지통에 보내는 실기는 하지 않는다. 합성 데이터로 곡만 복원/녹음 유지/후보 ID·순서 유지/취소/계정 전환/수신을 검증한다. 설치 후 기존 데이터 보존·화면 연결을 확인하며 개인 데이터의 삭제·복원 조작은 별도 사용자 요청 없이 실행하지 않는다.
