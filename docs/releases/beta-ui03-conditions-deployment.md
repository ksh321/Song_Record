# UI03 컨디션 추가·이름 변경 — 서버 반영 준비

USER-181 선택: 컨디션도 직접 추가하고 이름을 변경한다. 기본 네 항목과 녹음당 하나 선택을 유지하며, 변경한 이름은 이후 선택에 사용한다. 이미 저장된 녹음의 당시 이름은 보존한다.

## 적용 범위

- 기존 계정별 `condition_definition` 구조에 생성·이름 변경 API를 다시 연결한다. 선택 목록에서 제거하는 기존 시안 동작은 archive이며 정의나 과거 녹음을 물리 삭제하지 않는다.
- V34는 녹음의 컨디션 선택 트리거 두 개를 교체한다. 새 선택은 본인 계정의 활성 정의만 허용하고, 같은 코드를 유지하는 수정은 당시 이름을 보존한다. 기존 정의·녹음·V16 이력 행을 변경하지 않는다.
- 앱 설정과 녹음 입력의 컨디션/태그 수정 버튼, 목록 조회·계정별 동기화·충돌 표시·백업 가져오기 연결을 반영한다. 새 사용자 정의를 먼저 동기화한 다음 녹음이 참조한다.
- API·작업자만 잠시 재시작하고 기존 서명의 베타 앱을 데이터 보존 업데이트한다. 업로드 잠금, 계정·녹음 원본, 방화벽·로그인·결제 설정을 유지한다.

## 사전 조건과 복구

실행 직전 스키마33, 세 서비스 healthy, 검증된 이미지·설정 해시, 작업 대기/실행0·개인 삭제 대기0, 업로드 잠금, 26시간 이내 암호화 백업 성공을 확인한다. 다르면 중단한다.

배포 전후 계정/곡/플리/녹음 수·보관량과 키·하트·아이콘·컨디션 정의·녹음 당시 이름·과거 이력의 내부 비교 지문을 대조한다. 비밀값과 개인 메타데이터는 출력하지 않는다. DB 컨테이너와 볼륨을 재생성하지 않는다.

실패하면 기존 compose·이미지로 복귀하고 서비스 상태를 확인한다. DB를 복원하거나 행/열/이력을 삭제하지 않으며 V34의 소유권·과거 이름 보호 트리거는 유지한다. 실패 시 새 앱을 설치하지 않는다.

준비 스크립트 `.local/workflow/prepare-ui03-condition-deployment.py`는 기본값이 준비만 수행하는 모드다. 실제 서버 적용은 이 범위의 별도 승인 후 실행한다. 실기는 새 녹음 없이 설정에서 시험 컨디션 추가·이름 변경·재실행 유지와 서버 저장을 확인한다. 시험 항목을 선택 목록에서 제거하더라도 기존 녹음과 관계를 삭제하지 않는다.
