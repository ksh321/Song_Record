## 구현

- V25: 계정 revision, 소유자·세션에 결합한 5분 nonce 재인증, 10분 확인증 준비, 상태 전용 해시/시각/작업 기록. 서버 검증한 OIDC provider/sub가 현재 계정의 연결 로그인 수단과 정확히 일치해야 준비한다. 준비만으로 탈퇴하지 않으며 10분 내 5회 제한.
- 앱은 환경·서버·계정별 확인증과 동일 제출 op_id를 FlutterSecureStorage에 쓰고 다시 읽어 확인한 뒤 최종 동의를 받는다. 손상·저장 실패·다른 계정 scope를 덮어쓰지 않는다. 만료 준비의 교체는 서버 410 확인과 새 ACTIVE 소유자 재인증이 필요하다. 확인증은 로그/URL/백업 ZIP에 포함하지 않는다. 보호된 색인으로 로그아웃 화면에서도 상태만 조회할 수 있다.
- `POST /account/deletion-requests`: 일반 Bearer·등록 기기·최근 재인증 증명·전용 확인증·base_revision·ALL_ACCOUNT_DATA·confirmed=true. 기존 멱등 트랜잭션과 USER_SYNC/계정 잠금으로 DELETING·모든 세션 폐기·USER 원장·ACCOUNT_DELETE Job·상태 활성화·영수증을 함께 기록한다. 실패하면 모두 롤백한다. 접수 응답은 확인증 원문을 포함하지 않는다.
- 접수 응답이 유실돼도 전용 상태 조회로 확인한다. 일반 세션이 차단된 뒤 새 제출을 만들지 않는다. 앱은 해당 계정 핸들만 닫으며 진행 중 갱신 응답이 탈퇴 계정을 재활성화하지 못한다. 다른 계정을 로그아웃시키거나 개인 파일을 여기서 지우지 않는다.
- 전용 `GET /account/deletion-status/{id}`는 일반 Bearer 대체 불가, 잘못된 ID/토큰404, 유효 확인증 만료410, 접수 후30일, DB에 유지되는 분당60회 제한, no-store. 상태/시각/retrying만 반환하며 개인 식별자·이메일·객체키·삭제 대상 목록을 반환하지 않는다.
- 세부 상태·운영 백업 지연 안내는 P23-07에서 검증한다. 접수 단계에서 삭제 완료·모든 URL/외부 사본 회수를 주장하지 않는다.
