# P20-02 곡만 휴지통 이동 (원수)

- 승인: P20-01~10, 현재 6.1 Sol/medium 직접 구현·별도 검토. 원본 계획905~906, 설계539~550, R092.
- POST /v1/songs/{id}/trash SONG_ONLY: 현재 미리보기 확인값을 같은 계정 트랜잭션에서 재검증하고, 서버 시각부터 7일의 삭제 배치와 이전 연결·연결 revision·목록 정보를 보존한다.
- 곡은 TRASHED, 목록 항목은 기존 위치 그대로 숨김. 연결 녹음은 ACTIVE·미연결로 바꾸며 제목/가수/키/메모/티어/태그/조건·파일·고정·used bytes를 유지한다. 대표/자동 선택만 해제하며 STORED 파일은 ORPHAN_KEEP으로 보존한다. 이미 물리 정리 중이면 안전하게 충돌 처리한다.
- 같은 operation 재실행은 원래 결과를 반환한다. 확인값이 바뀌면 변경 없이 DELETE_PREVIEW_CHANGED. 다른 계정·없는 곡·지원하지 않는 모드는 거절한다.
- 변경: SongTrash, SongController/Configuration, RecordingEditing.snapshot 내부 재사용, OpenAPI, 모바일 Song 삭제 시각 검증, 서버/모바일 회귀 및 실제 MySQL 검사.

## 검사·별도 검토
- API build 전체 PASS; 최종 SongTrashTests 3개 PASS. H2에서는 보존·목록 위치·이전 연결·고정·파일·멱등·확인값 변경·정리 중 충돌 검증.
- Flutter 전체 980개 PASS. 이후 추가한 수신 검사 포함 최종 영향 73개 PASS, analyze: No issues found. 휴지통 UPSERT는 영구 삭제 tombstone을 만들지 않고 서버 삭제 시각과 원본을 보존한다.
- 현재 모델 별도 검토: 잠금 순서, 소유권, 서버 만료 시각, 기존 휴지통 제외, 전체 거래 롤백, 실제 MySQL V6 이력 제약 대조. 발견한 기록 순서 문제를 수정해 녹음 연결 해제 전에 이전 연결을 저장하고 목록의 previous_song_id도 함께 저장했다. 최종 영향 검사 재통과.
- 실제 MySQL 마이그레이션·자산·고정·목록 검사 추가. 로컬 Docker daemon 접근 불가이므로 이 실행 결과는 대상 SHA CI에서 확인하며 로컬 통과로 기재하지 않는다.
- 이번 단계는 서버 처리/수신 계약이다. 승인 업로드는 P20-03, 함께 삭제는 P20-04, 오프라인·복구·영구 정리는 후속 원본 번호, 화면·실기는 P20-10에서 연결한다. 이번 단계 설치 실기는 해당 없음이며 통과 실적이 아니다.

## 학습 개념
- 휴지통 이동은 영구 삭제와 구분해야 한다. 복구에 필요한 이전 연결을 변경 전에 저장하고, 녹음 파일은 곡의 삭제 상태와 별도로 보존한다.
