# P22-11 새 환경 복원 검증 — 사용자 승인 대체 환경

## 범위와 환경
- 원본 계획 p00998~1000/R114의 새 대상 복원 확인. 사용자는 노트북·폰 한 대만 가능하다고 확인하고 에뮬레이터 대안을 승인한 뒤 계속 진행을 요청했다. 기존 두 번째 물리 기기 대기는 철회했다.
- 실제 폰 SM-A546S → 노트북 신규 Android 36 에뮬레이터 SongRecord_P22_Fresh. 새 대상은 최초 검증 앱 설치 전 패키지가 없었고 앱 원본 파일이 없었다. 기존 폰 앱/DB 삭제·초기화는 하지 않았다.
- 모델: 현재 대화 6.1 Sol/medium 직접 구현·검사·별도 코드 검토. 추가 모델/하위 에이전트 없음.
- 합성 계정·검증용 19종 서버 응답을 사용한다. 실제 서비스 로그인·운영 서버 연동·두 물리 기기 검증은 포함하지 않는다. 이 근거만으로 출시 준비 완료를 선언하지 않는다.

## 실제 실행
- 폰에서 실제 ExportZipWriter로 곡·녹음·플레이리스트 정보3개와 AAC 파일1개를 생성, 노트북을 거쳐 새 에뮬레이터로 전달했다. 원본 ZIP SHA256: 59e716c9772434d189e9a10d34d147d7b37cde6ac02486f65eca6ebdf3b0cf79.
- 에뮬레이터에서 실제 ImportZipReader → Android 음원 검사 → 명시적 검증 동의 → identity/후보/충돌/대표 계획 → 계정 DB 저널 적용 → 결과 대조 → AndroidAudioPlayer 재생 완료 이벤트를 확인했다. 정보3·파일1, LIVE/키+2/메모/티어/목록 이름 보존, 파일 검증 직후 중단→계정 저장소 재개·같은 ZIP 재적용 무중복을 확인했다.
- 누락 시험은 **폰 원본을 바탕으로 노트북에서 만든 합성 변형**이다. 정보4·파일1·선택했으나 기기에 없는 파일1. SHA256: 70c53abfd8464ff6a5e377edb032b1282a2dedfa5635c3e82fffeb34c37e671d. 실제 에뮬레이터 결과 TARGET_PASS. 누락 녹음은 재생 가능 원본이 없고 전체 복원 완료로 표시하지 않는다. 녹음 제목/가수 스냅샷·Asia/Seoul·시간대 오프셋540도 보존했다.
- 동일 Android 실행에서 V22/V43: 영구 삭제 원장 우선·같은 TJ의 ACTIVE 정식 UUID 매핑과 녹음 연결·버전/메모 보존·TRASHED/PURGE_PENDING 보류를 실제 계획 함수와 검증된 서버 프레임으로 확인했다. **읽기/계획 검사이며 실제 서버 쓰기 검사가 아니다.**
- V48: 합성 KY 목록 항목만 보류, TJ 후보와 정상 음원 선택 유지. V24: 다른 소유자 거절·ZIP 경로 탈출 거절·외부 파일 미생성. 전체 손상/부분 동의 등 앞 P22의 검증 근거도 유지한다.
- 목록 이름 복원은 실제 DB에서 확인했다. 목록 항목의 실제 서버 적용·서비스 계정의 최종 관계 확인은 이번 설치본 범위에 포함하지 않았다. 출시 시 P25의 실제 서비스 통합 검증에 남겨 둔다.

## 발견·수정과 검토
- timezone_id를 UUID로 검사하던 오류를 수정했다. 시간대 문자열은 비어 있지 않은 64자 이내 문자열, 실제 자원 ID는 기존 UUID 검사를 유지한다.
- 서버에 없는 UUID도 최신 로컬 초안과 다르면 LOCAL_ONLY_UUID_CONFLICT로 보류하여 덮어쓰지 않는다. 검사 기대값 약화 없이 데이터 보존 근거로 검토했다.
- 중단 재개 시 기존 불변 저널을 사용하도록 계정/원본 ZIP 전체 digest 조회를 추가했다. 같은 export ID라도 내용이 바뀌면 거절한다.
- 변경 파일: import_validation.dart, import_conflicts.dart, import_apply_store.dart 및 해당 회귀 테스트, tool/import_transfer_verification.dart·p22_fixture.dart. 합성 fixture·검증 앱에 인증 값/사용자 녹음 없음.
- 별도 검토에서 원본 완료 조건·diff·계정 경계·삭제 우선·파일 검증·불변 저널·누락 분리·검사 결과를 현재 모델로 대조했다. 실제 서버/목록 항목 적용 근거가 없는 한 해당 범위를 통과로 확대하지 않는다.
