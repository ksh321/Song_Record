# P20-07 묶음·개별 복원 (원수)

- 원본 계획919~921, 설계555~557·925~927, R096·R097. 요청/관측 6.1 Sol/medium, 현재 모델 직접 구현·별도 검토.
- 서버 보관 기간 안에서 같은 묶음의 곡·녹음을 선택 복원한다. 곡만 삭제 당시 분리한 ACTIVE 녹음은 분리 버전이 그대로일 때만 다시 연결한다. 이후 다른 곡으로 옮긴 연결을 덮어쓰지 않는다.
- 곡이 영구 삭제된 경우 선택 녹음은 미연결로 복원한다. 원본 파일·정보·용량은 보존하고 대표·해제된 고정은 자동 재지정하지 않는다. 보존된 기존 고정은 그대로 둔다.
- GET 휴지통은 계정 범위·서버 날짜/UUID 키셋을 사용하며 현재 휴지통 대상이 없는 완료 묶음은 숨긴다. 과거 삭제 이력은 삭제하지 않는다.
- V6 삭제 이력 불변 트리거·기존 마이그레이션을 유지한다. 새 V23의 deletion_batch_work에 명령 base_revision을 보관하고 기존 이력은 작업 버전1로 연결한다. 만료 연장 없이 멱등 재실행·충돌을 처리한다.
- 변경: TrashRestoration/Listing/Controller/Configuration, V23, OpenAPI, API 경로 계약 검사, H2 복원 검사와 실제 MySQL 공유 시나리오, 마이그레이션 순서 검사.

## 검사·별도 검토

- H2 복원5개 중 재연결 시험의 준비 곡이 삭제된 곡과 같은 TJ 번호였음을 확인해 다른 검증 후보 번호로 수정했다. 기능 로직 실패와 구분한다.
- 전체 서버 검사 첫 실행712개 중 API 경로 계약1개 실패: 새 Controller를 실제 경로 대조 목록에 추가하고 batchId 경로명을 명세와 일치시켰다. 나머지 실행 검사 통과, 실제 MySQL 조건부82개 skip은 통과 실적으로 쓰지 않는다.
- 계약 검사143 경계 사례 PASS. 최종 전체 서버 결과와 대상 SHA의 필수 CI는 실행 결과 확인 후 기록한다.
- 현재 모델 별도 검토: 인증 우선·계정 스코프·선택 대상 검증·서버 만료·원본 이력 불변·잠금 순서·후속 연결 보존·파일 정책 버전 갱신·전체 트랜잭션 롤백·멱등 응답 대조. H2만으로 확인되지 않는 MySQL FK/트리거/JSON 동작은 필수 CI에서 검증한다.
- 목록 꼬리 복원·중복 제거는 바로 다음 P20-08 연결 범위이며 이번에는 목록 행을 변경하지 않는다. 서버 단계 설치 실기 해당 없음, UI 필수 실기는 P20-10.

## 학습 개념

- 삭제 당시 이력은 불변 증거이고 복원 요청 버전은 현재 작업 상태다. 둘을 분리하면 과거 만료를 바꾸지 않으면서 반복 요청과 동시 변경을 판별할 수 있다.

- 최종 gradlew build --offline 전체 PASS(1분8초), 실행630개 통과/조건부82개 제외(총712). 계약143 경계 PASS, diff 공백 검사 PASS.

- 실제 MySQL CI에서 JDBC DATETIME 반환이 LocalDateTime인 반면 H2는 Timestamp여서 캐스트 실패(P20-07-JDBC-TIME-01)를 확인했다. 두 표현 모두 명시적 UTC로 처리하도록 복원·목록 경로를 보완했다. 수정 시도1, 이전 SHA 이력은 보존하며 최종 SHA에서 실제 MySQL 재검증한다.
- 날짜 처리 수정 후 복원5개·API 계약 영향 검사 PASS. 현재 모델 별도 검토에서 두 JDBC 반환 경로와 UTC 비교/표시를 대조하고 실제 MySQL 휴지통 조회도 회귀 검사에 포함했다.

- 713f052 실제 MySQL81개 PASS. 통합 서버 검사에서는 기존 KaraokeRegistrationTests의 전체 문자열 MR→LIVE 치환이 무작위 암호화 토큰까지 바꾸는 독립 원인(P20-07-FIXTURE-TOKEN-01)이 확인됐다. version_code 필드만 치환하도록 수정하고 인증 검증·실패 기대값은 유지한다. 수정 시도1, JDBC 문제와 합산하지 않는다. 관련 녹음 복원·검색 등록 영향 검사 PASS.
