# P19-02 — 등록곡 목록 추가

## 범위와 구현
- 원본 P19-02와 R079: 같은 계정의 활성 TJ·MANUAL 내 곡을 목록에 추가한다. 서버가 `tj:<번호>` 또는 `manual:<곡 ID>` 키를 계산하며 같은 목록의 중복은 기존 항목 ID·위치를 반환한다.
- 서버 소유 계정·활성 곡·부모 revision 검증, 멱등성 기록, 계정 동기화 잠금과 곡→목록 잠금 순서를 적용했다. 새 항목과 부모 revision·변경 피드는 같은 트랜잭션에서 저장한다. 중복 반환은 revision·변경 순번을 늘리지 않는다.
- 모바일 실제 목록 상세에서 내 곡 선택과 기존 내구 큐 전송을 연결했다. 전체 항목 응답·부모·요청 완료는 한 트랜잭션으로 적용한다. 응답 유실 재시도는 원래 요청 본문·해시를 유지한다.
- 중복의 동일 revision 완료 허용은 검증된 항목 추가 응답으로 제한한다. 일반 수정의 revision 상승 조건은 유지한다. 이후 pull·영구 삭제보다 오래된 응답이 로컬 데이터를 되살리지 않도록 기존 완료 방어를 재사용한다.
- 변경 영역: 서버 playlists 서비스·라우트·보안, 모바일 목록 상세·목록 저장소·요청/응답·재시도·전체 항목 수신, API 계약과 관련 검사.
- 후보 추가·연결·다중 선택·정렬·제거는 후속 P19-03~09 범위이며 이 작업에서 완료로 확대하지 않는다.
