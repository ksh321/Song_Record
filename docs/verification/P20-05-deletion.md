# P20-05 녹음 개별 휴지통 이동 (원수)

- 원본 계획914~915, 설계533·553~556·919~920, R094·V21. 요청/관측 6.1 Sol/medium, 현재 모델 직접 구현·별도 검토.
- base_revision과 pin_release_confirmed를 검사한다. 현재/대기 고정이 있으면 확인 없는 삭제는 409로 거부한다. 같은 멱등 요청은 같은 묶음과 시각을 반환하며 새 요청으로 기존 휴지통 만료를 늘리지 않는다.
- 해당 녹음만 서버 시각의 7일 휴지통으로 이동하고 이전 연결/분리 버전을 보존한다. 곡·목록은 유지한다. 해당 대표와 자동 선정만 해제하고 기존 정책 재계산 작업을 제출한다.
- P20-04의 원자적 업로드 취소·예약 해제·고정 해제 경로를 재사용한다. 대기 교체 대상만 삭제하면 관계없는 현재 고정은 유지한다. 실제 파일·메타데이터·used 용량은 영구 삭제 확인 전 유지한다.
- 변경: RecordingTrash/Controller/Configuration, H2 RecordingTrashTests, 실제 MySQL 공유 시나리오, OpenAPI.

## 검사·별도 검토
- gradlew build --offline 전체 PASS(1분7초), 계약 검사 143 경계 사례 PASS. 실제 MySQL은 조건부 로컬 skip을 통과 근거로 쓰지 않고 최종 SHA의 필수 CI에서 확인한다.
- 별도 검토에서 재계산 작업 제출·대기 고정 삭제의 현재 고정 보존 확인을 보완해 영향 검사를 추가했다. 버전/계정 범위·변경 전 이력·7일 시간·파일 회계·FK/잠금 순서·멱등·역할/대표 해제 대조.
- 최초 패키지 내부 parseId 참조의 접근 오류는 자체 엄격 UUID 판독으로 수정했다. 보완 검사에서 작업 표 열 이름 job_type 대신 실제 type을 사용하도록 수정했다. 원인은 별개이며 원시 로그는 .local/workflow/p20-05에 보존한다.
- 이 단계는 서버 처리로 설치 실기 해당 없음. UI와 고정 재선택 안내의 필수 실기는 P20-10에서 확인한다. 필수 CI 완료 전 미완료.
