# P20-04 곡과 녹음 함께 휴지통 이동 (원수)

- 원본 계획911~912, 설계535~544·553~555, R094. 사용자 승인 P20 전체, 요청·관측6.1 Sol/medium 직접 구현·별도 검토.
- SONG_AND_RECORDINGS: 서버 미리보기 범위의 현재 연결 ACTIVE 녹음만 곡·숨김 목록과 같은 삭제 배치에 넣는다. 서버 deleted_at·7일 purge_after를 사용하고 연결 이력을 변경 전에 저장한다. 기존 TRASHED 녹음은 배치·시각·revision을 바꾸지 않는다.
- 고정 해제·대기 업로드 취소를 같은 거래에서 처리한다. 삭제할 대기 교체 대상만 없어지면 관계없는 현재 고정은 유지한다. 삭제할 현재 고정의 슬롯은 해제한다. 다른 녹음의 정보/파일은 삭제하지 않는다.
- 기존 UploadRecovery의 시도별 reserved 해제·취소·작업 lease 펜스를 재사용한다. 이미 STORED 파일·메타데이터·used 용량·로컬 원본은 유지하고 물리 삭제는 P20-09의 확인 경로에서 처리한다. 재실행은 원래 응답을 반환해 중복 차감하지 않는다.
- 변경: SongTrash, TrashRecordingEffects, 서버/H2·실제 MySQL 검사, Recording 변경 수신의 선택적 UTC deleted_at·원본 보존 투영, 공용 OpenAPI/예제.
