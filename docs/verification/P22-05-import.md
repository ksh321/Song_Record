# P22-05 UUID와 TJ 매핑

- 계획 원본 p00980~982·설계10.2(p00587~593)·R110 및 기존 TJ 문자열/삭제 상태 계약을 대조했다. 6.1 Sol/medium 원수 직접 구현·현재 모델 별도 검토.
- planImportIdentities는 검증된 ImportConsent와 19엔터티 ImportServerBaseline을 받는 읽기 전용 계획이다. 소유자와 현재 guard를 전후 확인하며 원본 백업/서버/DB에는 쓰지 않는다.
- 영구 삭제 원장 UUID 및 현재 PURGED 상태를 먼저 차단한다. 새 UUID의 같은 TJ는 활성 canonical UUID에 매핑하고, 휴지통·삭제 대기·다중 활성/백업 내부 중복 번호는 보류한다. TJ 앞자리0을 제거하지 않는다. UUID/정체성 불일치와 삭제된 녹음의 파일 설명·자산·태그 관계도 보류한다.
- 녹음·목록 참조와 입력 대기 draft/선택/폼의 song_id만 매핑한다. 녹음 UUID·당시 제목/가수·버전·키·메모는 유지한다. 다른 canonical에 재사용되는 새 SONG/원본/역할 행을 그대로 적용하지 않아 기존 곡 메모·버전·대표/보관 선택을 덮어쓰지 않는다. 원본 자료는 승인 소스에 그대로 보존한다.
- 실제 파일 후보는 영구 삭제 녹음에서 제외한다. 보류된 새 관계의 파일은 복원 가능한 정보가 없으면 보류한다. 기존 같은 UUID의 정보가 있는 파일 후보도 후속 파일 설명/충돌 대조 전에는 적용 권한이 아니다.
- 영향13개 PASS·Flutter 전체1117개 PASS·분석지적0. 실제 19엔터티 프레이밍/해시·인증된 같은 계정 기준을 ImportPreflight로 읽은 뒤 활성 별칭·삭제원장 우선·녹음 삭제/관계·TRASHED/PURGE_PENDING·앞자리0·중복·정체성·입력 대기·소유자/guard 및 스냅샷 보존을 확인했다. 원본 노트/버전 및 백업 JSON은 변경되지 않는다.
- 현재 모델 별도 검토 PASS: 삭제 먼저/재생성 우회 없음, 메모 자동 덮어쓰기 없음, 참조와 UUID 보존, 후보/보류 구분 및 순수 계획 경계를 대조했다. 검토에서 중복 TJ·UUID 불일치·삭제된 녹음 관계를 보완해 최종 회귀를 다시 통과했다. 소스 해시와 로그는 Git 제외 .local/workflow/p22-05/에 보존한다.
- 내부 매핑 작업으로 추가 폰 실기 없음. KY·revision·대표/고정·적용/재개와 제품 결합은 P22-06~11에서 이어간다. 커밋 후 필수 Flutter CI를 확인한다.
- 학습: 같은 번호라도 UUID 삭제 이력은 먼저 확인해야 한다. 현재 canonical 참조를 재사용하는 것과 백업의 과거 메모/상태를 덮어쓰는 것은 서로 다른 동작이다.
