# P22-03 파일 전체 검증

## 범위와 구현
- 원본 계획 P22-03·설계 10.2/10.3·R108/R109와 기존 R070 음원 계약을 대조했다. 원수 요청/관측 6.1 Sol/medium, 현재 모델 직접 구현·별도 코드 검토.
- ImportData는 외부 JSON 필수 필드·동일 schema/소유자/export ID/기준 시각·metadata 개수·자원 ID·중첩 구조와 개인 정보 필드 허용 목록을 확인한다. 중복 JSON 키·허용되지 않은 필드·객체/스칼라/UUID 배열 형식 오류를 거절한다. 기존 신뢰된 export checkpoint와 외부 ZIP 파서를 구분한다.
- ImportValidator는 필수 manifest/data JSON·허용 파일 목록 및 모든 포함 음원의 실제 SHA-256·크기·AAC 형식을 검사한다. 누락/손상 오류를 모으며 오류가 있으면 wholeBackupValid=false다. 기존 DB/정상 파일 쓰기 API는 없다. 별도 부분 복원 선택은 P22-04에 연결한다.
- AndroidImportAudioProbe·ImportAudioInspector는 실제 app-private cache 하위 경로만 읽고 6MiB/1음원·AAC-LC·48kHz·모노·0초 초과 361초 이하를 확인한다. 전체 MediaCodec 디코딩·실제 PCM 길이와 헤더 길이 대조, 출력량/30초 시간 제한을 적용한다. Dart 대기는 35초 제한. 경로·예외·음원 원본은 오류 메시지에 출력하지 않는다.

## 실제 검사·실기
- 영향 17개 PASS: 실제 export ZIP 왕복, 해시/누락/잘못된 형식·계정·필수 JSON·중복키·개수·구조·UUID 배열·361초 경계·취소와 기존 합성 원본 보존.
- Flutter 전체 1,096개 PASS, analyze 지적 0, searchVerification 검증 APK 빌드 PASS. Git 제외 .local/workflow/p22-03/ 검사 로그로 보존.
- R5CW618VA1M 실제 USB·잠금 해제·보존 install -r 확인. 합성 48kHz/모노 AAC만 사용하는 별도 검증 앱에서 전체 디코딩/ZIP 검증·해시 손상·잘린 파일·cache 밖 거절/원본 보존 4개 통과 화면을 확인한다. 최종 설치 결과 근거는 installed-ui-final.xml. 이 결과는 두 번째 실제 기기 복원이나 사용자 녹음 재생의 통과가 아니다.

## 검토·중단 이력
- 현재 모델 별도 검토: 필수/중첩 JSON 신뢰 경계, 해시 검사 전 native probe 미실행, 계정/취소 fence, cache canonical 경로, 디코더/출력량/시간 제한·자원 해제, 데이터 적용 없는 결과 및 정상/손상 구분을 대조했다. 검토 중 헤더 확인에 전체 디코딩·실제 길이 대조를 보완하고 361초 계약·외부 JSON 값 형식을 맞췄다.
- 2026-10-11 사용자 노트북 종료 요청으로 전체 검사를 중단했고 미커밋 변경·최초 시작값을 보존했다. 2026-10-12 재개해 남은 검사부터 수행. 시험 기준 누락·정적 타입/문법 지적은 각각 보완했으며 다른 원인을 합산해 모델을 올리지 않았다. 전체 변형 APK 빌드는 필요한 검증 앱 한 종류로 좁혔다.
- 명시 중단 구간을 원수 실행 시간에서 제외하고 일반 검사·CI·사용자 대기는 포함한다. 구독 차이는 중단 동안 같은 계정의 다른 사용량이 섞일 수 있다.
- 검증 후 일반 커밋/푸시와 필수 Flutter CI 완료를 대조한다. 완료 SHA/CI는 실제 결과 확인 후 추가한다.

## 학습
