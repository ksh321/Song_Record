# P22-01 계정과 서버 상태 확인

## 범위·근거
- 계획 원문 p00969~970, 설계 10.2(p00583~597), R107/V22/V24. 원본 DOCX 해시와 해당 문단을 대조했다.
- 현재 대화6.1 Sol/medium 원수 직접 구현·검사·별도 검토, 승인 끝P22-11. P21 최종4064da2/CI38143344521 완료 근거 유지. P08 기존서버 완료범위와 P10·P20 기준 보존, 재구현 없음.

## 구현
- POST /v1/imports/preflight는 먼저 실제 AuthSession으로 인증한다. 백업 schema_version=1·source_user_id는 비교값이며 인증을 대신하지 않는다. 다른 계정은403,잘못된 구조는400,무인증은401. 동일 요청의 idempotency 경계·스냅샷 제한·기존19entity 삭제원장을 재사용한다.
- Flutter ImportPreflight는 같은 로그인 계정을 요청 전·응답 후 확인하고 전체19entity 소유자·페이지·프레임 해시·기간을 확인해 읽기 전용 기준을 만든다. 대조 전 DB/파일에 백업을 적용하지 않는다. BUILDING은 준비 완료가 아니며 오프라인 우회가 없다.
- 기존 snapshot/export 요청의 전송 계약은 유지했다. 신규 가져오기 화면·적용은 후속P22에 연결한다.

## 검증·검토
- 영향5개: 삭제표식 포함 전체 기준,기존SQLite 상태 보존,타계정ZIP,실제로그인 불일치,응답중계정변경,해시손상,타계정페이지,준비중 상태를 확인한다. 초기 fixture에 삭제표식이 없던 오류를 실제표식·해시재계산으로 보완했다.
- 서버HTTP는 무인증·타계정·스키마·추가인증필드 거절과 인증된 같은계정의 수락/캐시금지를 검사한다. 실제 작업 생성은 기존 SnapshotBuildStore/JobQueue 회귀를 재사용한다.
- 현재 모델 별도 검토: source_user_id를 인증에 사용하지 않음,session fence,공유 트랜잭션 진입조건,전체 검증 전 기존 데이터 미변경,기존 sync/export 회귀 대조. 최종 검사 결과 및SHA/CI는 실제 결과 확인 후 기록한다.
- 내부 계정/형식 대조 작업으로 이 번호에서폰 조작 없음. 복원·재생은 후속설치본 검증에 연결하며 두번째실제기기 대기와 빈별도앱 검증을 구분한다.

## 학습
