# P03-06~08 도메인 규칙 검증

## 구현 범위

### 녹음 스냅샷

- 저장 완료 시 `recording_id`, 현재 `song_id`, 곡명, 가수, 키, 버전, 메모를 한 묶음으로 만든다.
- 시각은 UTC로 고정하고 원래 시간대 ID와 UTC 오프셋을 함께 보존한다.
- 재연결은 현재 `song_id`만 바꾸며 당시 표시 정보는 변경하지 않는다.

### 곡 기본값과 사용자 수정 표시

- 키와 버전에 각각 `edited` 표시를 둔다.
- 곡 선택을 바꾸면 수정하지 않은 항목만 새 곡 기본값을 따른다.
- `곡 기본값 적용`은 두 항목을 명시적으로 덮어쓰고 수정 표시를 해제한다.

### 정렬과 녹음 역할 선택

- 제목 정렬 버전은 `SR-SORT-1`이다.
- 계약 공백 제거, 한글 조합 정규화, ASCII 소문자화, 한글→영문→숫자→기타→빈 값 순서를 적용한다.
- 숫자 묶음은 자연수로 비교하고 최종 동률은 UUID 바이트 순서로 해소한다.
- 대표 녹음은 사용자가 명시한 유효 후보만 사용한다.
- 최신 녹음은 `recorded_at` 내림차순, 동률이면 ID 오름차순이다.
- 최저 등급은 D→C→B→A→S이며 미정은 제외한다. 같은 등급은 최신 시각, ID 순으로 해소한다.
- 후보 자격은 ACTIVE, SAVED, 유효한 파일 manifest를 모두 만족해야 한다.
- 한 녹음이 여러 역할을 맡을 수 있으며 결과 ID 집합에는 중복을 넣지 않는다.

## 자동 검증

Flutter와 Spring Boot가 각각 다음을 확인한다.

1. 녹음 재연결 후 스냅샷이 유지되는지 확인한다.
2. 사용자가 수정한 키는 곡 변경 후 유지되고 수정하지 않은 버전만 갱신되는지 확인한다.
3. 명시적 기본값 적용이 두 값을 덮어쓰고 수정 표시를 초기화하는지 확인한다.
4. `fixtures/contracts/sorting.json`의 모든 순서가 앱과 서버에서 같은지 확인한다.
5. `fixtures/retention/selection.json`의 RET-01~04 역할 선택 결과가 같은지 확인한다.
