## 근거와 구현

코드구현계획서 v1.0 P05-03: 탭별 이동 스택·원래 목록 스크롤·선택한 플레이리스트를
보존하고 상세와 선택기를 닫으면 실제 진입 위치로 돌아간다. UI_REFERENCE의 뒤로가기와
모달 취소 규칙도 따른다. 원본 설계 자료는 수정하지 않았다.

- `AppShell`: 기존 탭 순서·첫 방문 생성·녹음 패널 유지 구조에 탭별 Navigator를 연결한다.
- `TabNavigator`: 탭별 Navigator와 문맥을 소유하고 활성 탭만 Android 뒤로가기를 처리한다.
  비활성 탭 콜백에서도 pop하지 않도록 명시적으로 막는다. 현재 탭 재선택은 해당 탭의 첫 화면까지 돌아간다. 루트 화면은 재생성하지 않는다.
- `TabNavigation.openPage<T>`: 호출한 탭에 화면을 쌓고 typed 결과를 실제 호출자에게 돌려준다.
  상단 뒤로가기도 현재 Navigator의 maybePop을 사용한다.
- 설정은 기존 AppShell의 루트 Navigator에서 연다. 설정 아래 상세/선택기 스택은 유지한다.
- `selectedPlaylistId`는 탭 수명 동안 유지하는 UI 선택이다. 선택 확정만 반영하고 취소는
  기존 선택을 바꾸지 않는다. 다른 탭과 상태를 공유하지 않는다.
- 실제 목록 화면은 고유 PageStorageKey를 사용한다. 유지된 route 위에 상세를 쌓으므로
  상세·탭·설정 왕복이 기존 목록 위치를 초기화하지 않는다.

- 상세에서 상단/Android 뒤로가기: 같은 목록의 같은 위치로 복귀.
- 상세 → 플레이리스트 선택 → 샘플 A 확정 → 다시 선택기 → 취소: A 유지.
- 선택기 → 설정 → 뒤로가기: 선택기로 복귀. 다시 뒤로가기: 원래 상세로 복귀.
- 선택기/상세를 둔 채 탭 왕복: 각 탭의 화면·선택 문맥이 독립적으로 유지.
- `lib/main.dart`로 돌아가 실제 앱에서 녹음 중 탭/설정 왕복 후 상태 유지·종료·재생을 확인.

### 탭 재선택 동작 변경

사용자 요청: 현재 선택된 하단 탭을 다시 누르면 해당 탭의 첫 화면으로 돌아간다.
5개 탭에 공통 적용하며 상세·선택기를 닫는다. 다른 탭으로 전환했다 돌아올 때는
기존 스택을 유지한다. 첫 화면의 스크롤 위치·확정된 플레이리스트 선택·녹음은 유지한다.
이미 첫 화면일 때 다시 눌러도 화면이나 녹음 서비스를 재생성하지 않는다.
선택기를 닫을 때 새 선택을 확정하지 않는다.

변경 전 사용자 노트북 분석은 문제 없음(3.0초), 전체 테스트는 69개 통과했다.
재선택 변경 후 사용자가 미리보기의 각 탭 재선택 → 첫 화면 복귀가 정상임을 확인했다.
실제 앱에서도 녹음 중 현재 탭 재선택·다른 탭/설정 왕복 후 녹음 상태 유지·종료·재생이
정상임을 보고했다. 이 실기 결과는 사용자 보고에 근거한다.
재선택 변경 후 분석·테스트의 마지막 출력은 아직 전달받지 않아 정확한 통과 개수를 기록하지 않는다.
커밋·push 및 해당 커밋 CI 확인은 남아 있다.
