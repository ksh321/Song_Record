# P22-09 적용과 중단 재개

- 계획 원문 p00992~994·설계10.3·R112·기존 import_jobs/import_items와 AccountStore 큐/파일 보존 계약을 대조했다. 사용자 지정 6.1 Sol/medium 원수 직접 구현·현재 모델 별도 검토.
- import_apply_store.dart는 기존 DB 테이블에 계정별 import_job_id·변경 불가 명령·항목별 결과·파일 이동 단계를 기록한다. 새 테이블/DB 초기화 없이 기존 저장 구조를 재사용한다. 같은 job·manifest·계획은 재사용하고 다른 계획으로 재사용하면 거절한다.
- 각 항목은 기존 MutationRequest 계약을 통과하는 CREATE/PATCH만 실행한다. 과거 삭제/복원 큐를 무작정 재생하지 않는다. 기존 _saveEdit의 op_id 지문·baseline/예상 로컬 값·소유권 검사와 순서 있는 후속 변경을 재사용한다. 항목의 DB 변경·큐 등록·완료 개수는 같은 거래이며 실패하면 함께 취소된다.
- 검증 후 준비한 앱 전용 임시 파일만 읽는다. 최대6MiB 설명·크기·SHA를 다시 대조하고 MOVING→VERIFIED→COMMITTED 저널을 남긴다. 기존 _preserveDownloadedAudio가 동일 파일을 재사용하고 다른 파일·정리 fence는 거절한다. 이동 직후 프로세스가 중단돼도 재개 시 체크섬을 대조한다. 영구 삭제 원장/로컬 tombstone을 먼저 검사한다.
- 한 번에 항목 하나를 처리하며 완료 항목은 재실행하지 않는다. 계정/승인 guard는 비동기 경계에서 재확인한다. 실패는 PAUSED와 항목의 안전한 IMPORT_RECHECK_REQUIRED를 저장하며 키·원본 바이트·외부 경로를 로그/저널에 넣지 않는다.
- 영향8개 PASS: 항목 커밋 후 중단/재시작·같은 백업 재준비 무중복, 계획/manifest 변경 거절, 파일 검증 후 중단/재시작·해시 재사용, 기존 다른 파일 무변경, 임시 바이트 변경 차단, 승인/계정 변경 차단, DB 변경/완료 거래 원자성, 파괴 작업 재생 거절. 합성 바이트로 저널/DB 경계를 검사했으며 실제 AAC 형식 검증은 선행 P22-03 근거다.
- 현재 모델 별도 검토 PASS: 새 큐 요청과 과거 큐 재생 구분, 원자성·재개·op_id 중복 방지, 기존 파일/초안 보존 및 계정 guard 대조. 상위 가져오기 화면은 검증·충돌 선택·최신 baseline을 대조한 명령만 봉인해야 한다. 실제 정보/파일 집계는 P22-10, 화면 및 설치본 전체 결합은 P22-11에서 수행한다.
- 학습: 파일 시스템과 DB를 하나의 거래로 묶을 수 없으므로, 먼저 의도를 기록하고 파일을 검증한 뒤 DB 결과를 확정한다. 재시작은 기록과 실제 바이트를 다시 대조해야 한다.

- 최종 일괄 로컬 검사: 영향8개·Flutter 전체1152개 PASS·분석 지적0. 추가 필수 실기는 전체 가져오기 결합 P22-11에서 수행한다.
