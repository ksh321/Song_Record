# P19-01 — 목록 CRUD

## 범위와 완료 기준
- 원본 계획서 P19-01: 생성·이름 변경·조회·삭제, 중복 이름 허용. `오늘`도 날짜·앱 종료로 초기화되지 않는 일반 목록이다.
- R078·D05 이름 정규화·D07 목록 영구 삭제 계약을 적용한다. 곡·녹음·오디오 삭제는 이 작업의 범위가 아니다.
- P18 완료 근거를 보존하고 P19-02~09는 각각 원본 순서로 이어간다.

## 구현
- 서버 `playlists/`: 소유 계정 CRUD, 1~100 유니코드 코드 포인트 이름, revision 충돌, 요청 재전송, 영구 삭제 증명과 재생성 차단. 삭제 본문·항목은 커밋된 정리 작업으로 제거하며 곡·녹음은 보존한다.
- 모바일 `features/playlists/`: 실제 계정 저장소 목록 화면, 생성·이름 변경·삭제 확인/취소. 오프라인 삭제는 전송 대기로 안내한다.
- 기존 동기화 큐에 목록 CREATE/PATCH/DELETE를 연결한다. 미전송 생성 후 변경·삭제의 순서, 불변 요청·재시도 이력을 보존한다.
- 로컬 DB v13: 기존 요청 바이트·해시를 복사해 DELETE 허용 범위만 확장하고 목록 후속 변경 검증을 추가한다. 기존 스키마 검색본은 보존한다.
- 별도 검증 계정 00000000-0000-4000-8000-000000001901을 사용한다. 기존 녹음·개인 계정 데이터는 초기화하지 않는다.
