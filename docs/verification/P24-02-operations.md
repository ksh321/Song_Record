- 원본 계획 p01039–p01040, 설계14.1 p01063–p01097, R121·R122 및 기존 업로드·인증·잠금 계약을 대조했다.

## 연결 구현과 보존

- [초기 운영 설정 실행서](../runbooks/operations-policy.md)의 10개 설정을 staging 환경·신규 가입·UserEntitlement 기본값·예약·일일 승인·실제 URL 발급·작업자 공유 슬롯/기한에 연결했다.
- staging/prod 신규 가입은 global-first DB 잠금 뒤 현재 계정 수와 이미 생성된 로그인 식별자를 재조회한다. 기존 계정 로그인·삭제 전용 기존 소유 확인은 베타 입장 제한을 적용하지 않는다.
- 기존 UserEntitlement, 진행 시도, 서버 사본, 원본, 개발 DB를 유지한다. 전체 용량은 실제 사용+예약과 DB/배포 설정의 작은 한도를 비교하고 신규 예약만 제한한다. schema/runtime 상한을 넘는 설정은 배포 전에 거부한다. 정보·조회 경로에 전역 업로드 잠금을 추가하지 않았다.
- 작업자 중첩 다운로드/검증/확정은 설정된 단일 기한·세마포어를 공유하며 실제 reader 종료 후 슬롯을 반납한다. 검증 이미지 태그를 명시적으로 선택해 이전 작업 이미지/로그를 보존했다.

## 실제 검사·현재 모델 별도 검토

- 연결 구현 후 전체 서버 build PASS: 759개, 실패0·오류0·skipped87(통과 실적 제외). 이후 UTC 한도 회귀 및 MySQL 공통 검사를 추가해 영향 범위만 재검증한다.
- 베타 마지막 자리 경쟁/기존 로그인·신규 entitlement 설정은 같은 공통 assertion을 H2와 CI 전용 새 MySQL DB에 연결했다. 로컬 개발/검증 DB 삭제 없이 CI 일회용 DB만 정리하는 기존 패턴을 사용한다.
- 기존 예약 동시성·용량/임시 관측 경계·멱등 재사용·UTC 재설정·URL 한도·메타데이터 저장/조회 분리·중첩 작업자 슬롯/기한·설정 오류 차단을 검증한다. 기존 앱 코드는 이번 번호에서 수정하지 않았으며 앱/실기 전체 반복 불필요.
- 최초 컴파일에서 설정 policy 필드와 기존 revision 변수 이름 충돌 발견 → 해당 필드 명시, 재검증 PASS(원인 P24-02-POLICY-SHADOW, 수정1회). 공통 검사 추출의 누락 import는 별도 원인 P24-02-CHECK-IMPORT, 수정1회. Gradle 인수 위치 오류는 명령 구성 오류로 분리. 서로 다른 실패를 합산하지 않는다.
- 검토 중 재시작 이미지 기본값이 이전 P24-01로 돌아갈 수 있는 문제를 확인했다. 마지막 정상 배포 태그를 비밀값 없는 로컬 파일에 원자적으로 보관하고, 재개는 이를 사용한다. 임의 태그 거부·재개 단위 검사와 실제 재주입/HTTPS PASS.
- 현재 모델 별도 검토: 원본 완료 조건·actual diff·기존 데이터/계정 격리·한도 경쟁·부분 실패 rollback·최종 결과 대조. 사용자 지정 모델 유지, Worker/Reviewer/별도 모델 호출 없음.
