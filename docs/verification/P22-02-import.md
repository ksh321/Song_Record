# P22-02 ZIP 구조 검사

- 원본 계획 P22-02·설계 10.2·R108의 경로/자원 제한을 대조했다. 원수 6.1 Sol/medium으로 직접 구현·별도 검토했다.
- ImportZipReader는 저장형·deflate·ZIP64 중앙/로컬 헤더를 대조하고 절대/상위/Windows 별칭 경로, 중복·파일 부모 충돌, 심볼릭 링크·특수 파일을 거절한다. 새 임시 디렉터리만 만들며 기존 DB·녹음에는 쓰지 않는다.
- 항목 100,000개, JSON 합계 100MiB, 음원별 6MiB, 압축비 100:1, 중앙 디렉터리/이름/확장 길이와 CSV 자원 한도를 적용한다. 실제 해제 바이트·CRC·헤더 겹침도 확인한다. 시작 전 실제 여유 공간 조회를 요구하고 16MiB 여유를 둔다. 계정/취소 fence와 실패 정리는 생성한 임시 경로에만 적용한다.
- 정상 저장형·압축형·로컬 ZIP64, 악성 경로·중복·링크·압축비·신고/실제 크기·개수 초과, 공간 부족·취소에서 기존 파일과 입력 ZIP 보존을 검사했다. 17개 PASS, Flutter 전체 1,079개 PASS, analyze 지적 0. 실행 근거는 Git 제외 .local/workflow/p22-02/에 있다.
- 현재 모델 별도 검토 PASS: 경로 alias/부모 충돌, 헤더와 실제 해제량, 소유 임시 경로의 정리 범위, 계정 변경·취소 및 기존 export 회귀를 대조하고 최종 소스 해시를 저장했다.
- 필수 JSON·음원 포맷/해시는 P22-03에서 전체 검증한 뒤 적용한다. 이 번호는 내부 구조 검사이며 추가 폰 조작 없음. 필수 Flutter CI 대기.
- 학습: ZIP에 적힌 크기는 신뢰할 수 없으므로 실제 해제량을 제한하고 기존 데이터와 분리한 임시 공간에서 검사해야 한다.
