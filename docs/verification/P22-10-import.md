# P22-10 복원 후 보관 재계산

- 원본 계획 p00995~997·설계10.2(p00589/592)·R113/R114와 서버 SnapshotSourceRows의 현재 보관 선정·고정·파일 상태, 기존 UploadQueueStore 계약을 대조했다. 사용자 지정 6.1 Sol/medium 원수 직접 구현·현재 모델 별도 검토.
- import_outcome.dart는 작업 저널과 실제 서버·로컬의 entity/UUID 존재를 대조해 확인된 정보를 집계한다. 아직 존재하지 않는 계획 항목과 미완료 적용 항목은 대기로 남긴다. 파일 수는 포함 파일의 실제 앱 전용 체크섬을 다시 검사하며 누락·보류·충돌·대기를 따로 표시한다. 수치는 서로 다른 측정 축이며 단순 합산하지 않는다.
- refreshPolicy로 가져온 검증된 현재 계정 baseline의 SONG_CLOUD_SELECTION(대표/최신/최저 티어)·PIN_SLOT(current/pending) 합집합을 사용한다. 활성 SAVED·실제 검증 파일만 후보로 남기고 이미 STORED 파일은 제외한다. 백업의 과거 역할이나 파일 전체 집합을 업로드 허가로 사용하지 않는다.
- discoverImportUploads와 기존 UploadQueueStore의 선택적 only 범위를 연결했다. 기존 일반 discovery 동작은 유지하며 가져오기 후보 밖의 파일은 이번 발견에서 제외한다. 빈 집합은 큐를 만들지 않는다. 실제 큐는 기존 승인된 SAVED 서버 정보·명세 해시/크기·미전송 변경/매핑 fence 검사까지 통과해야 한다. 서버 보관 재계산은 기존 정보 동기화의 서버 정책을 유지하며 클라이언트에서 임의 권한을 만들지 않는다.
- import_outcome_view.dart는 정보·파일·누락·보류·충돌·대기·서버 정책 후보를 구분하고 남은 항목이 있으면 전체 성공을 표시하지 않는다. 후보와 실제 업로드 완료/용량 승인도 구분한다. SafeArea·스크롤을 사용한다.
- 영향8개 PASS·분석 지적0: 현재 역할/고정만 선정, 현재 역할 없음, DRAFT/휴지통/STORED/파일 없음 제외, 계정 거절, 실제 검증된 서버/로컬 정보와 없는 정보 구분, 분리 집계 화면, 원본 보존 업로드 회귀, 빈/다른 UUID 집합은 큐 생성 없음.
- 현재 모델 별도 검토 PASS: 과거 역할 무재생·현재 정책/계정·아직 미승인 정보 제외·원본 보존·전체 성공 오표시 방지 및 기존 큐 동작 대조. 전체 설치본 결합과 새 기기 실기는 P22-11에서 수행한다.
- 학습: 정보가 복원됐다는 사실과 실제 파일이 있는지, 서버가 그 파일을 보관할지는 각각 다른 결과다.

- 최종 일괄 로컬 검사: 영향8개·Flutter 전체1158개 PASS·분석 지적0.
