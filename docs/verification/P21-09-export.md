# P21-09 일관성과 삭제 경쟁 검증

## 근거와 보완

- 원본 계획서 v1.0 P21-09(p960–962), R102–R106, 설계서 백업 절, D10 및 P00-07 B07/B08을 대조했다. 기준 이후 편집, 명시적 파일 삭제, 연결 장애, 공간 부족을 검증하며 삭제를 되돌리거나 무기한 지연시키지 않는다.
- ExportAudioCollector/ExportController: 수집 이후와 캐시 ZIP 저장 재시도 전 현재 삭제·휴지통·원본 존재·파일 상태를 재확인한다. 삭제된 파일은 FILE_DELETED로 바꾸고 포함 파일 없는 새 ZIP을 검증한 뒤 사용한다. 원본 경로에 복사하지 않으며 명시적 삭제를 막는 전역 잠금을 두지 않는다.
- 외부 저장 도중 삭제가 확인되면 완료를 거절하고 누락 체크포인트를 남긴다. 이미 쓰인 외부 사본은 독립 사본이므로 임의 삭제하지 않으며 미완성 사본 가능성을 안내한다. 다음 재시도는 삭제된 원본을 복원하지 않는다.
- HttpPreservationDownload: 기존 인증된 preservation-url API를 재사용해 다운로드 뒤와 서버 파일의 최종 출력 전후 현재 접근을 확인한다. 실제 FILE_NOT_STORED 응답은 삭제 누락, 연결 오류는 다운로드 실패로 구분한다. API 인증을 R2로 전달하지 않는다. 만료된 사본 기준을 새 서버 커서로 바꾸지 않는다.
- 네이티브 저장은 작업별 CancellationSignal·열린 스트림을 관리해 취소/5분 제한 시 닫는다. 이전 작업 타이머가 새 작업 자원을 닫지 못하도록 분리했다. Dart 저장 대기도 6분 제한으로 정상 완료를 거절한다. 외부 URI 삭제·기존 파일 덮어쓰기·원본 변경 없음.
- 실제 Windows 재개 검사에서 문자열 구분자 비교가 안전한 경로를 거절하던 문제를 발견해 path.join/equals로 보완했다. 실제 링크·계정 경로 검사는 유지한다.
