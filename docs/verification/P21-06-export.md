# P21-06 음성 파일 수집

## 요구사항·구현
- 원본 계획서 v1.0 P21-06(p951–953), 설계서 10.1(p581), R104/D10.
- export_audio.dart: ACTIVE·미연결·완료 DRAFT 파일, 선택한 휴지통 파일을 같은 고정 data/manifest 범위에서 처리한다. 영구 삭제된 정보는 메타정보에 보존하되 파일 수집 대상에서 제외한다. 미완성 명세는 INCOMPLETE_RECORDING, 선택하지 않은 휴지통은 제외 항목이다.
- 기존 validRecordingFileSpec·PreservationObject·HttpPreservationDownload를 재사용한다. 서버 전용 파일은 순차 fetch·현재 계정 인증·세대/해시/크기/revision 확인 후 받는다. 원래 앱 음성 위치에 다운로드를 설치하지 않는다.
- 기기 정상 파일은 기존 AccountStore.readLocalAudio로 검증하고 다시 고정 명세의 SHA-256/크기를 대조한다. 파일당 최대 6MiB, 다운로드/읽기 대기 제한 35초(HTTP 기존 30초). 서버 다운로드 실패는 누락으로 기록하며 자동 무한 재시도하지 않는다.
- 오프라인 서버 전용은 OFFLINE_SERVER_ONLY, 다른 기기 전용은 FILE_NOT_ON_DEVICE. 손상 바이트는 CHECKSUM_MISMATCH, 삭제 경쟁은 FILE_DELETED. 취소·계정 변경·출력 디스크 실패는 작업을 중단하며 정상 완료로 표시하지 않는다.
- 계정 원자 읽기에 파일 상태/해시/크기/갱신 시각을 추가해 기준 뒤 삭제를 대조한다. 현재 녹음의 삭제 표식/수명과 파일 상태를 파일 전후 확인한다. 소스였던 로컬 파일이 사라지면 서버 다운로드로 되살리지 않는다.
- account_paths.dart의 exports/{export_id}/ 전용 계정 경로만 허용한다. 경로 이탈·링크를 거절하고 account_store.stageExportAudio는 별도 .part 쓰기/flush/해시·길이 확인 후 임시 최종 파일로 변경한다. 기존 정상 stage는 일치할 때만 재사용하고 원본 audio/는 덮어쓰지 않는다.
- 자동 앱 정리와 같은 AccountStore 실행 경계에서 한 파일의 읽기/쓰기를 유한하게 직렬화한다. 전체 백업 동안 cleanup_fence를 잡지 않는다. 명시적 파일 삭제는 파일 사이에 진행 가능하며 기존 정리 확인 펜스 규칙을 약화하지 않는다. 서버 자동 정리 자체를 지연시키거나 완료로 추정하지 않는다.
- P21-07에서 ZIP/영속 작업 기록, P21-09에서 전체 내보내기 기간의 편집·삭제·네트워크·공간 경쟁과 최종 단계 재검증을 연결한다. 이번 수집 검사만으로 전체 ZIP 완료라고 하지 않는다.
