# P24-06 삭제 원장 재적용 검증

상태: 구현·로컬 검사·현재 모델 검토·실제 MySQL/R2 원장 확인 완료. 최종 커밋·푸시·필수 CI 대기. P24-07 미착수.

- 원본 근거: 계획 P24-06 p01051–01052, 설계 10.4 p00600, R101·R125·R126 및 기존 P23 계정 삭제 계약. P24-05 완료 SHA `f310225`의 실제 전체 SHA는 최종 커밋 근거에서 확인한다. 원수 요청/관측 gpt-6.1-sol/medium.
- 구현: V30 별도 삭제 확인 원장, `BackupDeletionFence`와 staging/prod 강제 연결, 작업자의 원격 확인 대기·재예약, 별도 암호화 원장/세대/소유자 정리, 새 일회용 복원 DB에만 적용하는 원장 SQL, 전체 R2 목록과 중단된 파일/지점 식별. 기존 데이터·사본 보호·lease·완료/사용량 판정은 유지.
- 서버 전체 빌드: 770개 중 681개 실행 PASS, 환경별89개 skipped. 이후 영향24개 실패/오류/skip0 PASS, MySQL DATETIME/Timestamp 보완2개 PASS. 실제 MySQL CI에서 V30과 공유 `BackupFenceDatabaseChecks`를 검사하도록 연결한다. skipped를 통과로 계산하지 않는다.
- 로컬 도구: 원장·7일 정리·30일 제한·백업/Windows 암호화/환경 영향37개 PASS, 일회용 DB 경계·세대/소유자 SQL5개 PASS. 모델 호출·새 패키지/유료 API 없음.
- 실제 MySQL: V30 분리 DB 적용, 최초 WAIT → 원격 암호화 저장·재독 → 동일 revision ACKNOWLEDGED 확인. 시험 대기를 취소해 원격 취소·활성 세대 복원 허용 PASS. 원본 생성 음성 해시 보존. 실제 사용자/운영 파일 삭제는 실행하지 않음.
- 실제 R2 별도 시험 접두사: 실제 DB 덤프·음성 암호화 재독, 삭제 세대 사본을 제거한 과거 지점의 복원 필터, 사용자 차단, 지점 만료 정리 PASS. 7일은 격리 시험 영역의 제어 시계로 검증했고 실제7일 대기 실적이 아니다. 해당 시험 객체만 제거, 실제 백업·원본 보존. 정리 후 전체 R2 목록 unknown_artifacts=false PASS.
- 실제 새 일회용 MySQL 소규모 스키마: 새 세대 보존·옛 세대만 NONE·녹음 기록 유지·삭제 소유자 제거·다른 소유자 보존·영구 원장 적용 PASS. 해당 생성 시험 DB만 정리, 원래 DB 불변. 전체 서비스 복원 훈련은 P24-07의 별도 범위다.
- 검토 지적과 해결: 동일 잠금으로 백업 게시/정리 경합 방지, DELETING 계정의 새 백업 게시 차단, 원격 원장 없을 때 복원 거부, 확정 삭제의 취소/옛 DB 덮어쓰기 거부, generation 범위로 새 사본 보존, 미분류 객체의 부재 추정 금지, 중단 정리 재개, 원격 확인 대기와 실패 예산 분리, 복원 DB 경계/소유자 FK 순서·기록 보존 확인. 현재 모델 직접 검토이며 별도 에이전트 검수 아님.
- 문제 P24-06-JDBC-DATETIME-001: 빈 목록만 통과하던 변환에서 실제 비어 있지 않은 MySQL 행 조회 실패. Timestamp 전용 변환을 LocalDateTime도 지원하도록1회 보완, 회귀·실제 조회 PASS. 분석/수정 후 재검증 실패0회. 승인 검토 시간 초과는 실행 전 환경 사건이며 한 번의 이미지 빌드 재시도 성공, 코드 실패 횟수에 합산하지 않음.
- 실제 상태: 비AI 원장 감시·일일 백업 감시 연결, 기존 계정/정리 작업자 스케줄 비활성 유지. 외부 운영 배포 없음. 다음은 P24-07 실제 서비스 복구 훈련. 현재 직접 사용자 행동0건.

학습 개념: 삭제 원장은 복구 대상 DB 밖에서도 살아 있어야 하며, 같은 녹음이라도 세대가 다르면 별개 파일이다. 원격 저장의 확인 응답과 실제 삭제·다른 계정 보존은 각각 검증한다.
