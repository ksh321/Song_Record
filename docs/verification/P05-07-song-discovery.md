## 구현

- 코드구현계획서 P05-07, UI_REFERENCE의 새 곡 찾기 항목, HTML의 목록 문맥을 따른다.
- 공통 바텀시트에 인기 차트와 검색을 동일 스타일·동일 높이의 가로 2열 카드로 배치했다.
  팔레트의 최소 높이 156, 간격 12, 모서리 18, 내부 여백 18/16을 사용한다.
  긴 문구와 큰 글꼴에서는 높이가 늘어나며 시트 내부를 스크롤할 수 있다.
- 목록 ID가 전달된 경우에만 내 곡에서 선택을 제공한다. 모든 선택 결과에 원래 목록 ID를
  포함한다. 취소·바깥 터치·뒤로가기는 null이며 호출자의 선택이나 목록을 바꾸지 않는다.
- 앱 내 곡 탭의 새 곡 찾기는 실제 인기 차트/검색 탭으로 이동한다. 아직 연결 전인 데이터
  영역은 준비 상태로 표시한다. 목록 문맥의 연결은 독립 메모리 샘플로 검증할 수 있다.
- PlaylistSongPicker는 전달받은 등록곡에서 곡명·가수 부분 검색을 수행한다. 앞뒤 계약 공백과
  영문 대소문자를 정리한다. 기존 곡 행을 재사용하고 이미 담긴 곡은 추가됨으로 표시한다.
- 추가 콜백에 목록 ID와 SongId를 전달한다. 성공 시에만 추가됨으로 바뀌고, 요청 중 연타를
  막는다. 실패 시 기존 결과를 유지하며 실패한 곡을 재시도한다. 각각의 추가는 즉시 반영되며
  완료/뒤로가기는 이미 성공한 추가를 취소하지 않는다. 서버 멱등성 검증을 대신하지 않는다.
- 목록 변경 또는 화면 폐기 후 예전 요청의 완료가 새 화면 상태를 바꾸지 않도록 했다.
- 공통 상태는 로딩·빈 결과·오류·대기를 명시적으로 구분한다. 오류만 재시도를 제공하며,
  대기는 회전 표시를 사용하지 않는다. 모션 감소에서는 로딩도 정적인 아이콘과 문구를 쓴다.

## 연결 경계

현재 계정의 ACTIVE 등록곡 조회, 플레이리스트 저장, TJ 후보의 중복 해소는 호출자가 담당한다.
`includedSongIds`에는 같은 TJ 후보로 이미 담긴 항목까지 해소한 SongId를 제공해야 한다.
이 단계에는 DB/API 호출이 없으며 이후 실제 서비스 연결에서 계정·휴지통·권한·중복을 다시 검증한다.
P05-06에 기록한 서버 ORIGINAL 비영 반음 CHECK 불일치는 실제 저장 API 연결 전 해결해야 한다.
검수용 상태 전환 패널과 샘플 데이터는 앱의 main 진입점에 포함하지 않았다.
