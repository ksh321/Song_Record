# P20-06 오프라인 삭제 표시 (원수)

- 원본 계획916~918, 설계553~554, R095·X08. 요청/관측6.1 Sol/medium, 현재 모델 구현·별도 검토.
- LocalRepository.prepareTrash는 받은 ACTIVE 자료/버전과 변경 전 유효 자료를 대조해 기존 TRASH 큐에 저장한다. 로컬 화면은 즉시 숨기며 deleted_at을 기기 시각으로 만들지 않는다. 곡만 삭제 시 연결 녹음은 미연결로 표시하며, 함께 삭제 대기 시 해당 곡의 녹음도 숨긴다. 관계없는 서버 원본과 파일은 변경하지 않는다.
- 곡 요청은 이미 확인한 서버 preview_version을 그대로 보존한다. 재연결 후 대상이 바뀌면 서버 409로 중단하고 재확인하며, 미리보기를 자동 재발급해 삭제 범위를 넓히지 않는다. 개별 녹음은 base_revision/고정 해제 확인을 전송한다.
- 기존 의존 관계·불변 전송 요청·재시도·계정 격리 경로에 POST trash를 연결했다. 전체 응답의 묶음·주 자료·자식 범위·실제 UTC·정확한 7일을 검사한 뒤 같은 DB 거래에서 확인 처리한다. 늦은 응답은 더 최신 녹음/영구 삭제를 되돌리지 않는다. 미전송 변경과 원본은 보존한다.
- 서버 휴지통은 수정 대기 초안으로 ACTIVE처럼 되살리지 않는다. 원본 제거와 PURGED/삭제 장부는 기존 수신 보호 경로에서만 처리하며 기기 시계로 제거하지 않는다.
- 변경: account_store, LocalRepository, MutationRequest, DependencyPlanner, MetadataDispatcher, trash_receipt, offline_trash_test.
