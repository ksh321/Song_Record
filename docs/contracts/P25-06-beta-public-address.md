# P25-06 베타 웹 주소·서명 준비안

현재 상태(2026-10-16): 두 IP 제한 HTTPS와 Google·카카오 실제 웹 소유 확인, 별도 beta 서명 설치본의 두 제공자 로그인/재실행, 폰의 암호화 서명 복구 사본 대조를 완료했다. 새 UTC 음원 포함 암호화 백업과 격리 복원/해시·디코딩도 통과했다. USER164 범위는 본인1명 비공개 베타이며 전체 인터넷 게시/외부 초대 승인이 아니다. 최종 커밋/필수CI 대기, Sol6.1/medium 사용자 예외 유지. 아래 날짜별 기록은 당시 상태이며 현재 완료 항목을 되돌리지 않는다.

## 실제 남은 조건

- 기기/서버 사본 재생과 확정 보관 표시 검사는 통과했다. 현재 별도 beta 패키지의 사용자 소유 서명 APK를 설치/로그인 검증했으며 기존 staging 앱은 보존했다. 정확한 APK/인증서 지문은 P25-06 검증 기록에 남긴다.
- 웹 계정 삭제는 실제 발급한 Duck DNS 호스트와 등록된 웹 origin/콜백으로 두 제공자 소유 확인을 통과했다. 현재 기존 두 IP의 제한 접속이며 일반 인터넷 공개/공개 시행일·국외 처리 안내는 외부 확대 전에 확인한다. 기존 숫자 IP 앱 연결과 호스트 이름 웹 로그인 등록을 구분한다.
- 기존 개인정보 준비본을 `python tools/prepare_beta_privacy.py`로 로컬 HTML로 변환한다. 원문 내용을 보존하고 공개 전 준비본임을 표시한다. 이것은 법률 검토나 실제 게시 증거가 아니다.

## 비용 없는 주소 후보와 실행 범위

Duck DNS는 무료 하위 도메인을 제공한다(https://www.duckdns.org/why.jsp). 사용자가 소유한 로그인으로 주소를 확보하고 기존 AWS 실험 IP를 연결하는 안이다. 예시 이름은 `song-record-beta-<고유값>.duckdns.org`이며 실제 가용성·사용자 선택·서비스 조건을 확인한 뒤 확정한다. 등록 전에 이름을 확정된 주소로 기록하지 않는다.

무료 하위 도메인도 공급자 장애·계정 유지·이름 회수 위험이 있다. 현재 단계의 베타 주소이며 장기 운영의 도메인 소유권을 보장하지 않는다. AWS와 R2의 기존 비용·무료량 조건은 바뀌지 않는다. 새 유료 서비스·자동 결제·AWS Paid 전환은 포함하지 않는다.

주소 확보 후 별도 인증서와 Google 웹 client origin/카카오 웹 redirect를 구체적으로 준비한다. 현재 Android 로그인 등록·IP 인증서·검증 앱 데이터는 보존한다. Google/카카오의 새 웹 로그인 접근 등록은 실제 저장 전 정확한 주소를 제시해 승인받는다. DNS 갱신 토큰이 필요한 경우 Windows 계정 암호화로 등록하며 AWS 전달은 별도 수신처 승인을 받는다.

공개 전에는 프록시 설정 초안과 경로별 접근 검사부터 만든다. 개인정보 페이지·계정 소유 확인·탈퇴 요청·확인증 상태 조회만 외부 공개 후보이며, 일반 앱 API는 기존 노트북/폰 접근 제한을 유지한다. AWS 443을 전체 허용하더라도 프록시에서 일반 API 제한이 사라지면 적용하지 않는다. DB·관리 포트는 공개 대상이 아니다. 개인 계정 시험 삭제·초대 메시지·전체 서비스 공개는 이 준비안에 포함하지 않는다.

## 서명 키 준비 범위

Play 개발자 계정이나 유료 가입 없이 베타 배포용 전용 키 생성·서명 빌드를 준비할 수 있다. 개인 키와 무작위 암호는 Git 제외 `.local/workflow/release/`에서 현재 Windows 사용자 ACL과 계정 암호화로 보호한다. 빌드에서만 보호된 임시 설정을 사용하고 끝나면 제거한다. 키/암호를 채팅·명령 인수·환경변수·Git에 출력하지 않는다. Gradle에는 비밀값 대신 임시 properties 경로만 전달한다.

생성 전 사용자 승인과 복구 보관 방법을 확정한다. 서명 변경은 기존 staging debug 앱에 덮어쓸 수 없으므로 기존 데이터를 삭제해서 설치하지 않는다. 새 설치 경계 또는 정식 배포 후보 패키지, Google/카카오의 정확한 인증서 등록을 대조한다. 기존 debug 인증서를 출시 인증서로 가정하지 않는다. 최초 설치·로그인 영향 검증과 산출물 SHA가 있어야 배포 준비 통과로 기록한다.

## 백업 시간 조건

2026-10-15 UTC 일일 복구점은 녹음 전 생성돼 음원0이다. 같은 복구점을 덮어쓰지 않고 10월16일 오전9시 KST 이후 첫 정규 백업에서 음원 포함 여부를 확인한다. 그 후 승인된 별도 임시 DB/계정의 격리 복구·파일 해시/디코드 검사를 수행한다. 현재 서비스 DB 대체나 사용자 원음 출력은 하지 않는다. 기존 서버 타이머는 이미 활성 상태이며 AI 자동 재개를 의미하지 않는다.
