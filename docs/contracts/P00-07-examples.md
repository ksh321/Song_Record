# P00-07 공통 수용 사례
- 2026-09-16 / 문서 버전 1.0
- [D09 스냅샷](../decisions/D09-materialized-snapshots.md) · [D10 백업](../decisions/D10-offline-backup.md) · [D11 상태 조회](../decisions/D11-deletion-status.md)
- 기대 결과 계약이며 실제 실행 결과가 아니다. P00-08 fixture 통합과 후속 구현 검증으로 연결한다.

| ID | 입력·상황 | 기대 결과 |
|---|---|---|
| S01 | 스냅샷 생성 중 다른 기기에서 곡 수정·삭제 | 모든 페이지는 같은 읽기 시점, 이후 변경은 기준 cursor 다음 로그로 수신 |
| S02 | 기준 cursor 조회와 데이터 읽기 | 동일 읽기 뷰, 미커밋 변경 누락을 cursor로 건너뛰지 않음 |
| S03 | BUILDING 부분 행 저장 후 조회 | 409 NOT_READY, 부분 사본 미노출 |
| S04 | 생성 중 서버 재시작 | 이전 부분 attempt 폐기 후 전체 재생성, 새 읽기 뷰와 혼합 금지 |
| S05 | READY 서버 재시작 | 원래 사본과 남은 TTL로 재개 |
| S06 | 준비 완료 29분59초 / 정확히30분 | 유효 / 410 만료. 조회로 연장 없음 |
| S07 | 만료 중 앱에 미전송 메모·파일 존재 | 새 사본으로 수신 staging 재시작, 미전송·파일 보존 |
| S08 | 전체 수신 전 앱 종료 | 현재 기준 DB 불변, staging 지점부터 유효 사본 재개 |
| S09 | 마지막 엔터티 해시 오류 | 기준 사본/cursor 교체 금지 |
| S10 | 같은 op_id 생성 재시도 | 같은 작업/사본, TTL 재설정 없음 |
| S11 | 타 계정 token / 다른 entity cursor | 접근/잘못된 cursor 거절 |
| S12 | 계정 동시 사본 2개 상태에서 추가 생성 | 429, 기존 유효 사본 유지 |
| S13 | payload 100MiB 초과 또는 전역 1GiB 예약 초과 | 용량 오류, 부분 게시 금지, 예약/임시 데이터 정리 |
| S14 | 스냅샷 수신 도중 탈퇴 접수 | 즉시 추가 조회 차단, 사본 정리 대상 |
| B01 | 로컬 음성1·2·3, 서버 전용a·b·c의 정보만 동기화 | ZIP 음성1·2·3, a·b·c 명세는 미포함 사유, 서버 자료 불변 |
| B02 | a·b·c도 로컬 정상 파일, 여섯 개 선택 | 여섯 파일 포함·해시 검사 |
| B03 | 다른 기기 최신 변경 미수신 | 포함 보장 없음 표시, 서버 최신 전체 백업으로 표시 금지 |
| B04 | 확정 서버 cursor 없는 오프라인 내보내기 | null·baseline incomplete, 로컬 부분 백업 표시 |
| B05 | 미전송·충돌 값 존재 | 기준 revision과 양쪽 값 보존, 자동 덮어쓰기 금지 |
| B06 | 온라인 전체 manifest 취득 전 30분 만료 | 새 스냅샷 기준으로 다시 취득, 기존 로컬 원본 보존 |
| B07 | 전체 manifest 고정 후 30분 경과 | 로컬 작업 계속 가능, 파일 다운로드는 현재 권한·삭제 확인 |
| B08 | 백업 중 명시적 서버 파일 삭제 | 누락 기록, 삭제 취소/무기한 지연 금지 |
| B09 | 백업 중 새 녹음 추가 | 기준 이후 항목으로 구분, 작성 중 ZIP에 임의 혼합 금지 |
| B10 | 앱 종료 후 임시 파일 정상 | 저장된 job/해시 검증 후 재개 |
| B11 | 디스크 부족·손상·외부 저장 중단 | 정상 완료 금지, 기존 정상 백업·원본 보존 |
| B12 | 만든 ZIP 이후 온라인 복귀 | ZIP 자동 수정 없음, 정보 동기화와 선별 음성 업로드만 별도 진행 |
| B13 | 녹음 중 백업 요청 | 안전 종료 성공 후 진행, 실패/취소면 백업 시작하지 않음 |
| B14 | 오프라인 ZIP에 영구 삭제된 목록 포함 후 가져오기 | 온라인 소유권·현재 삭제 표식 확인, 목록 부활 금지 |
| B15 | 계정 인증 토큰·탈퇴 확인증 | ZIP에 포함하지 않음 |
| D01 | 확인증 준비만 성공 | 계정 활성 유지, 준비 TTL10분 |
| D02 | 준비 응답 유실·저장 실패 | 탈퇴 미접수, 정상 인증으로 새 준비 가능 |
| D03 | 만료된 준비·타인 준비로 탈퇴 접수 | 거절, 계정 차단 없음 |
| D04 | 유효한 최종 탈퇴 접수 | DELETING·Job·확인증 활성화 원자적 반영, 일반 API 차단 |
| D05 | 최종 접수 응답 유실 | 미리 저장된 확인증으로 접수 여부 조회, 일반 세션 복구 금지 |
| D06 | 확인증으로 곡·파일·복구 API 호출 | 거절, 상태 조회만 가능 |
| D07 | 다른 준비 ID/토큰·추측 ID·이메일 조회 | 상태·개인정보 노출 없음 |
| D08 | 앱·서버 재시작 | 유효 확인증·영속 Job으로 조회/삭제 재개 |
| D09 | R2 삭제 실패 | 재시도 중, COMPLETED 금지 |
| D10 | 운영 DB/R2 삭제 완료·백업 남음 | BACKUP_CLEANUP, 백업 기한 안내 |
| D11 | 운영 백업 제거 확인 | COMPLETED, 시각 기록 |
| D12 | 접수 후 정확히30일 | 확인증 만료, 자동 연장/계정 접근 재개 없음 |
| D13 | 확인증 분실 | 재발급 복구 기능 없음 안내, 삭제 작업은 계속 |
| D14 | 오프라인 기기·앱 밖 ZIP 존재 | 모든 사본 원격 삭제 완료라고 표시하지 않음 |
| D15 | 7일 백업 정리 기한 초과 | 운영 경고·지연 표시, 시간만으로 완료 처리 금지 |

문서 완료 검토: 세 결정·만료/재개/인증/완료 표시·사례·요구사항 연결.
미실행: DB 일관 읽기/부하/재시작, 기기 ZIP 생성·가져오기, 탈퇴·실제 R2 삭제·운영 복구. V/X 실행·통과 수를 증가시키지 않는다.
