# P25-06 AWS 실험 작업자 활성화 승인안

상태: USER132가 `AWS 실험 자동 정리·삭제 작업자 활성화 허용`을 명시 회신했다. 아래 범위로 실행·검증하며 수동 업로드 잠금은 유지한다.

## 대상과 실제 확인

기존 AWS 실험 서버의 `song_record_experiment` DB와 `song-record-experiment-temporary` / `song-record-experiment-final` 두 비공개 버킷만 대상으로 한다. 원격 앱은 이미 이 전용 범위로 전환했고 기존 DB 컨테이너와 사용자2·인증정보2·세션2가 전후 동일했다. 이전 공유 키 파일은 관리자 전용으로 보존하며 새 활성 앱/백업에서 사용하지 않는다.

2026-10-15 실제 읽기 전용 확인: DB 확정 파일 참조0·확정 객체0·임시 객체0·누락0·미연결0·손상0. 개인 계정 삭제 대기0·삭제/영구 정리 작업0. 이 결과는 실제 녹음 업로드·삭제·복구를 검증했다는 의미가 아니다.

## 활성화할 동작과 제한

- `worker-policy.json`의 `upload=true`, `account_deletion=true`를 설정한다. API 역할에는 이 두 기능을 켜지 않는다. worker만 재기동하고 기존 API·DB 컨테이너의 동일성을 확인한다.
- 업로드 음원 검사·확정과 기존 `UploadScheduling`의 임시 파일 정리·일일 객체 대조를 실행한다. 임시 전송 만료 또는 DB 참조가 없는 확정 파일이 기존 유예 조건을 충족하면 해당 실험 버킷의 객체를 실제 삭제할 수 있다.
- 기존 worker의 보관 정책·휴지통 만료·파일 정리 작업도 적용된다. 고정/보관 근거와 동시성 검사·독립 백업 삭제 원장 ACK를 통과한 대상만 처리한다. 서비스에서 해제되거나 보존 기한이 지난 원격 파일은 실제 삭제될 수 있다.
- 개인 계정 탈퇴는 당사자가 앱의 인증·재확인 절차를 거쳐 요청한 경우에 처리한다. 이 승인으로 현재 계정의 탈퇴 요청을 만들거나 개인 데이터를 시험 삭제하지 않는다. 활성화 직전 삭제 대기0을 다시 확인하며, 예상 밖 기존 대기가 있으면 실행하지 않고 조사한다.
- 독립 암호화 삭제 원장을 30초마다 확인하고 변경/대기 ACK 또는 시간당 전체 검증 때 원격 상태를 검증한다. 실패하면 ACK·완료를 만들지 않으며 작업은 대기하고 기존 폰 경고로 알린다. 백업·복원 검사와 같은 파일 잠금을 사용한다.
- 실제 일일 대조의 시각·문제0과 건강 상태를 확인한다. 신규 업로드 수동 잠금은 이 활성화 단계에서 유지한다. 실제 음원 검사·필요 CI·나머지 베타 완료 조건은 별도로 남긴다.

## 승인에서 제외할 것

노트북/개발/운영 버킷 접근, 원본 개발 DB·앱 데이터 초기화, 기존 AWS 공유 키 파일 삭제/이동, Cloudflare 기존 토큰 폐기, 현재 개인 계정의 임의 삭제, 백업 보존 기간 단축, 전체 외부 공개, AWS Paid/Upgrade·새 정액 결제는 실행하지 않는다. 승인 거절을 다른 경로로 우회하지 않는다.

## 승인 필요 이유

자동 승인 검토는 작업자 재기동이 기본 정리·삭제 스케줄러까지 실행할 가능성을 지적했다. 기존 업로드/대조 승인만으로 개인 데이터 삭제 범위가 충분히 통제됐다고 확인되지 않아 실행을 거절했다. 읽기 전용 대조를 안전한 대안으로 완료했으며, 위 자동 정리·삭제 범위는 USER132의 명시 승인으로 실행한다. 정책상 삭제 대상이 실제 삭제될 수 있는 점을 이해하고 허용하는 선택이다.
