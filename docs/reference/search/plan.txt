[p00004] 개발 환경을 만든 뒤 실제 기기에서 녹음과 복구를 먼저 확인한다. 다음으로 계정별 로컬 저장과 서버 정보 동기화, 안전한 파일 보관을 구현하고, 제공된 UI에 기능을 연결한다. 마지막으로 삭제·백업·새 기기 복원과 운영 복구를 검증한 뒤 제한 베타로 진행한다.
[p00005] 이 계획은 26단계와 231개 세부 작업으로 구성한다. 각 작업에는 구현 내용과 완료 기준을 두고, 단계별로 선행 조건·코드 영역·근거를 표시한다. 설계서의 V01~V48과 추가 검수 X01~X12를 담당 단계에 연결한다.
[p00006] 문서 상태  실행 계획. 작업별 체크와 검증 결과는 구현 과정에서 기록한다. 아래의 완료 기준은 통과해야 할 조건이며 이미 통과했다는 뜻이 아니다.

[p00086] 녹음 파일은 Android 서비스가 영속 디렉터리에 먼저 마무리한다. 서버가 보관 대상으로 선정한 파일만 앱이 임시 PUT URL로 R2에 전송한다. 작업자가 실제 바이트를 검사해 별도 최종 객체와 DB를 확정한 뒤 서버 파일 보관 완료로 표시한다.

[p00116] 3 착수 전에 구체화할 계약
[p00117] 아래 항목은 이미 정해진 기능을 바꾸는 요청이 아니라, 코드가 같은 규칙으로 동작하도록 필요한 구현 계약이다. 각 제안은 결정 기록과 OpenAPI·공통 예제에 반영한 뒤 해당 기능을 구현한다. 의사결정 기록에는 선택·이유·영향·검증 결과를 남긴다.
[p00118] D01 기술과 버전
[p00119] 확정 시점  P01 전
[p00120] Flutter 안정 채널, Riverpod·go_router·Drift·Dio, Java 21과 지원 중인 Spring Boot 안정판, MySQL 지원 LTS를 시작안으로 삼는다. 조합을 빌드한 뒤 lockfile·Wrapper·이미지 버전을 고정한다. 녹음 플러그인 채택은 P02 실기 결과로 결정한다.
[p00121] D02 한국어 정렬 일치
[p00122] 확정 시점  P03·P08 전
[p00123] 앱·서버가 같은 한국어 정렬 키 규격과 비교 예제를 사용한다. 한글·영문·숫자·기호·동명·UUID 동률을 포함한다. 서로 다른 기본 collation이 같다고 가정하지 않는다. 오프라인 새 곡도 같은 키를 만들 수 있는 구현을 시제품으로 확인한다.
[p00124] D03 날짜와 필터 경계
[p00125] 확정 시점  P09 전
[p00126] 기간은 선택한 표시 시간대의 시작일 00시 이상·종료 다음 날 00시 미만을 UTC로 변환하는 안을 확정한다. 원래 녹음 시각과 당시 시간대는 보존한다. 녹음 제목순 동률도 최종 ID까지 명시한다.
[p00127] D04 기기 파일 상태 필터
[p00128] 확정 시점  P09·P18 전
[p00129] 서버는 실제 현재 기기 파일을 알 수 없으므로 서버 파일 조건과 기기 파일 조건의 API 의미를 분리한다. 제안은 전체 메타정보를 동기화한 로컬 DB에서 복합 파일 필터·정확한 개수·페이지를 계산하는 방식이다. 한 서버 페이지에만 후처리하지 않는다.
[p00130] D05 입력 문자 수
[p00131] 확정 시점  P03 전
[p00132] Java·Dart·DB의 길이 차이를 피하도록 Unicode 코드 포인트 기준을 시작안으로 정한다. 제목·가수 trim, 200자·2000자 경계와 이모지 사례를 같은 fixtures로 확인한다. 정규화가 사용자 표시값을 임의 변경하지 않게 한다.
[p00133] D06 컨디션 선택 수
[p00134] 확정 시점  P04·P09 전
[p00135] HTML은 컨디션 1개, 설계서 관계 테이블은 복수도 담을 수 있다. 첫 구현은 컨디션 0~1개·태그 복수·태그 필터 1개를 제안하고 API·UI·DB 제약을 함께 확정한다. 과거 이름 스냅샷과 archive는 유지한다.
[p00136] D07 목록 자체 삭제
[p00137] 확정 시점  P19 전
[p00138] 곡·녹음의 7일 휴지통과 목록 자체 삭제를 구분한다. 목록 삭제의 논리 삭제·동기화 표식·정리 시점을 명시한다. 목록 복원 기능을 별도 확정 없이 추가하지 않으며 곡·녹음은 삭제하지 않는다.
[p00139] D08 설정과 추가 보관 요청
[p00140] 확정 시점  P23 전
[p00141] 강조색의 기기별 저장 또는 계정 동기화 여부를 정한다. 초기 제안은 기기별 저장이다. 설계서의 보관 공간 요청을 위한 최소 API와 데이터 보존 범위를 추가 계약으로 정의한다. /storage/requests는 제안 경로이며 기존 확정 API가 아니다.
[p00142] D09 스냅샷의 실제 저장
[p00143] 확정 시점  P07·P10 전
[p00144] 30분 동안 여러 페이지가 같은 시점을 보려면 token만으로 부족하다. 제안은 짧은 일관 읽기로 만든 계정별 스냅샷 결과를 임시 저장하고 TTL 정리하는 방식이다. 보조 테이블·용량·만료·재시작을 명세에 추가하고 DB 트랜잭션을 30분 유지하지 않는다.
[p00145] D10 오프라인 백업
[p00146] 확정 시점  P21 전
[p00147] 온라인은 새 서버 스냅샷을 기준으로 한다. 오프라인 백업은 마지막 확정 사본과 로컬 변경·파일의 부분 백업으로 제공하는 안을 정한다. 서버 최신 포함을 보장하지 않는 표시와 snapshot_cursor 규칙을 정하고 최초 로그인은 계속 온라인으로 제한한다.
[p00148] D11 탈퇴 후 상태 확인
[p00149] 확정 시점  P23 전
[p00150] 계정 삭제 즉시 세션을 막으므로 일반 인증 API만으로 처리 상태를 보여주기 어렵다. 재인증된 접수에 묶인 제한된 상태 확인 수단 또는 소유 확인 웹 흐름을 정의한다. 삭제 상태 조회가 개인 데이터 접근 권한을 다시 열지 않게 한다.
[p00151] 외부 데이터의 출시 조건
[p00152] TJ·KY의 월별 차트는 양쪽 모두 서로 다른 완료 월 2개 이상의 실제 기간과 출처를 확인해야 한다. Manana의 monthly 표기만으로 임의 과거 연월 조회가 가능하다고 판단하지 않는다. 허용된 출처에서 확보한 월만 게시하며, 이용 조건·기간 검증을 충족하지 못하면 해당 출시 조건은 차단 상태로 남긴다. 조사 착수는 P00-03, 연동 완료 판정은 P16-08이다.
[p00153] 이 문서에서 기술 참고 문서를 확인한 것과, 앱의 상업적 데이터 이용 허가 또는 실제 월별 차트 연동을 확보한 것은 별개다. 외부 데이터의 계약·운영 근거는 구현 과정의 산출물로 관리한다.
[p00154] 4 전체 순서와 단계별 통과 조건
[p00155] 아래 순서는 1인 개발의 기본 실행 순서다. 녹음 위험은 P02에서 먼저 확인하고, 화면 공통 골격은 P05에서 준비한다. 실제 사용자 화면의 완성은 저장·동기화·파일 정책을 연결한 P17~P19에서 판정한다. 모든 후반 단계는 첫 출시 범위에 포함된다.

[p00338] 마이크 권한, microphone 서비스 선언·권한, 알림을 적용하고 보이는 화면의 사용자 동작으로 시작한다.

[p00341] AAC-LC 96kbps·48kHz·모노·M4A를 설정하고 실제 생성 파일의 형식을 확인한다.
[p00342] 완료  짧은 파일이 재생되며 목표 코덱·샘플링·채널을 만족한다.

[p00348] 완료  연속 종료 요청에도 파일·녹음 ID가 하나만 만들어진다.
[p00349] P02 06  복구 저널 기록

[p01204] 7 검증 목록과 완료 판정
[p01205] 서버 동시성은 실제 MySQL 통합 테스트, 녹음·잠금·입력 충돌·기기 이전은 실제 Android 기기로 확인한다. 단순 문구·색상 변경은 화면 검수로 확인하고 구현과 똑같은 내용을 반복하는 테스트는 만들지 않는다. 아래 행의 상태는 모두 미실행에서 시작한다.
[p01206] 공통 완료 기준  구현 내용이 저장소에 반영되고, 관련 계약·마이그레이션이 일치하며, 해당 실패 경로에서 데이터가 보존되어야 한다. 검증을 실행한 환경과 결과가 기록돼야 완료로 바꾼다.

[p01501] 먼저 현재 저장소와 진행 기록을 읽고 해당 작업의 선행 조건이 완료됐는지 확인해.기능·데이터·API·보관·삭제·동기화는 설계서 v1.11을 기준으로 하고, 화면은 HTML, 공통 조작은 UI_REFERENCE, 색상·치수는 JSON을 적용해.
[p01502] 이번 작업의 목표는 [목표]이고 완료 기준은 [계획서의 완료 문장]이야.기존 구현을 확인한 뒤 필요한 파일을 실제로 수정하고, 임시 데이터와 실제 기능의 연결 여부를 구분해.공통 컴포넌트와 Repository를 재사용하고 HTML 검수용 패널이나 샘플 서버 상태를 앱에 복사하지 마.계약에서 미확정인 항목은 관련 D 번호를 확인하고, 기존 확정 정책을 바꾸지 않는 구현 결정을 기록해.
[p01503] 검증은 이 작업의 완료 조건과 관련 V 또는 X 항목을 중심으로 수행해.기기·인증 설정·출처 이용 조건 때문에 실행하지 못한 검증은 미실행으로 기록하고, 가능한 구현과 로컬 확인은 마무리해.
[p01504] 끝나면 변경 파일, 동작, 실행한 검증과 결과, 남은 연결, 다음 작업 ID를 알려줘.실행하지 않은 검증이나 가짜 데이터만 연결된 기능을 완료로 표시하지 마. 진행 기록을 갱신해.
