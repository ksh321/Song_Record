# D07 — 목록 영구 삭제 안내와 삭제 전파
- 상태: 확정 / P00-06 / 2026-09-16
- 승인: 사용자 A안 + 영구 삭제 안내 후 삭제
- 관련: R078·R037·R041, P19-09
- 사례: [P00-06](../contracts/P00-06-examples.md)

## 화면 계약
삭제 전에 반드시 다음 확인창을 표시한다.

> 플레이리스트를 영구 삭제할까요?
> 이 목록과 목록 안의 구성·순서는 복원할 수 없습니다. 내 곡과 녹음은 삭제되지 않습니다.

버튼: 취소 / 영구 삭제. 취소는 변경·요청을 만들지 않는다. 삭제 확인 후 목록을 숨긴다. 목록은 7일 휴지통에 넣지 않고 실행 취소·목록 복원 기능을 제공하지 않는다. 곡·녹음의 기존 7일 휴지통은 변경하지 않는다.
오프라인이면 “목록 삭제 전송 대기”를 표시하고 계정별 큐에 보존한다. 서버 승인 전 “서버 삭제 완료”라고 표시하지 않는다.

## API와 경쟁 처리
DELETE /v1/playlists/{id}, Idempotency-Key: op_id, 본문 {base_revision}.
응답 200: {id, status:"DELETED", revision, deleted_at}. 같은 op_id·같은 본문 재시도는 같은 결과, 다른 본문은 409 IDEMPOTENCY_CONFLICT.
서버가 소유권과 revision을 확인한 뒤 삭제 상태·revision·변경 로그·삭제 UUID 원장·정리 Job을 한 트랜잭션으로 반영한다. 다른 계정은 404.
활성 목록의 revision 불일치는 409 REVISION_CONFLICT와 최신 소유자 목록 요약을 반환한다. 자동 재삭제하지 않고 최신 항목 수를 보여주며 영구 삭제를 다시 확인받아 새 op_id로 보낸다.
이미 삭제된 소유자 목록은 재삭제로 부활하거나 삭제 시각을 연장하지 않고 기존 삭제 결과를 반환한다. 삭제된 목록에 새 항목 추가·이름/순서 변경은 409 PLAYLIST_DELETED로 거절한다.

## 정리와 동기화
서버 승인 트랜잭션에서 목록·항목은 조회 및 수정 불가가 된다. 목록명·구성·순서의 본문은 커밋된 정리 Job의 다음 실행에서 제거하며 7일 복원 대기 기간을 두지 않는다. 실패 시 재시도하고 원장으로 삭제 상태를 유지한다. 정리 Job은 Song·Recording·녹음 파일을 삭제하지 않는다.
삭제 표식에는 계정·대상 UUID·타입·삭제 시각·revision 등 최소 정보만 남긴다. 활성 계정의 삭제 UUID 원장은 기존 R041에 따라 유지한다. 변경 로그 보존 만료는 원장 삭제 조건이 아니다. 계정 탈퇴에 따른 원장 제거는 계정 삭제 절차에 따른다.
다른 기기는 삭제 표식을 적용하고 로컬 목록 본문·항목을 정리한다. 오래된 기기 변경·백업의 동일 UUID 재생성을 거절한다. 기존 백업 파일 자체를 소급 삭제할 수는 없지만 앱 가져오기로 해당 목록을 부활시키지 않는다.
“영구 삭제”는 사용자 복원 불가를 뜻하며 모든 운영 백업의 즉시 물리 삭제 완료라는 뜻으로 안내하지 않는다. 새 목록 생성은 새 UUID로 가능하다.
