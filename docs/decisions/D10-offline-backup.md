# D10 — 오프라인 부분 백업
- 상태: 확정 / P00-07 / 2026-09-16
- 사용자 승인: 추천 A, 로컬 1·2·3 / 서버 a·b·c 예시 확인 후 승인
- 관련: R102~R107, V23·V24, P21·P22
- 사례: [P00-07 공통 사례](../contracts/P00-07-examples.md)

## 범위
온라인은 새 서버 스냅샷을 기준으로 로컬 미전송 변경·충돌 값·선택한 음성 파일을 합친다. 오프라인은 마지막으로 확정 반영한 서버 기준과 현재 로컬 변경·파일을 내보낸다. 첫 로그인은 계속 온라인이다.
오프라인에서도 메타정보·로컬 파일 보호를 위한 ZIP 내보내기는 가능하다. 서버에 있는 자료를 삭제하거나 덮어쓰는 동작이 아니다. 작성된 ZIP은 이후 연결·동기화로 자동 갱신되지 않는다.

| 자료 | 오프라인 처리 |
|---|---|
| 동기화된 개인 정보 | 마지막 확정 로컬 기준 포함 |
| 미전송 신규·수정·삭제 | op_id/base_revision과 변경을 별도 보존 |
| 충돌 | 기준값·서버 수신값·로컬 초안 보존, 한쪽 자동 폐기 금지 |
| 현재 기기 정상 파일 | 선택 범위 내 실제 복사·해시 확인 |
| 서버 전용 파일 | 메타/파일 명세를 아는 경우 기록, 파일 미포함 사유 OFFLINE_SERVER_ONLY |
| 다른 기기 전용 파일 | 아는 명세만 기록, FILE_NOT_ON_DEVICE |
| 아직 받지 못한 서버 변경 | 포함 보장 불가 |
| 계정 비밀·상태 조회 토큰·공용 차트 | 제외 |

예: 기기에 1·2·3, 서버에만 a·b·c라면 ZIP의 음성은 1·2·3이다. a·b·c의 정보가 기기에 동기화돼 있으면 정보는 포함하되 파일 미포함을 기록한다. a·b·c 음성도 기기에 있다면 선택 범위에 따라 여섯 파일 모두 포함할 수 있다.
다시 연결하면 신규 기록 정보는 동기화하지만 음성 전체를 무조건 업로드하지 않는다. 자동/고정 보관 대상·한도를 적용한다.

## manifest와 커서
기존 schema_version=1 형식에 아래 계약을 추가한다. 기존 import 구현이 없다는 현재 단계 기준의 스키마 구체화이며 이후 배포된 형식 변경은 버전 전환 절차로 처리한다.
- backup_scope: ONLINE_SNAPSHOT / OFFLINE_PARTIAL.
- created_at, local_cutoff_at, source_user_id, export_id(오프라인은 기기 생성 UUID).
- snapshot_cursor: 실제 서버가 발급하고 로컬에 완전 반영된 커서. 온라인은 새 사본의 기준, 오프라인은 마지막 확정 커서. 최초 동기화 미완료 등 확정 기준 없으면 null.
- server_confirmed_at 및 server_baseline_complete. null 커서를 0이나 현재 시각으로 위조하지 않는다.
- metadata_count, included_audio_count, missing_audio_count, 개별 파일 id·크기·길이·해시·포함 여부·누락 사유.
커서는 역사적 백업 기준이며 import 후 실시간 동기화 커서로 그대로 채택하지 않는다. 현재 삭제 상태 동기화와 소유권 확인은 기존 R107을 따른다. 오프라인 내보내기 허용이 오프라인 가져오기/새 로그인 허용을 뜻하지 않는다.

## 일관성·중단·완료
1. 녹음 중이면 안전 종료해 완료 파일과 DRAFT 정보를 보존한다. 사용자 취소/종료 실패 시 백업을 시작하지 않는다.
2. 메타정보·변경 큐를 로컬 읽기 기준으로 고정한다. 온라인 서버 기준과 로컬 변경의 시점이 다르면 provenance를 남겨 단일 동시 시점으로 과장하지 않는다.
3. 포함 파일은 버전/해시로 고정하고 복사 동안 앱 자체 정리에서 보호한다. 외부 삭제·명시적 사용자 삭제를 백업이 되돌리거나 무기한 지연시키지 않는다.
4. 선택 파일 다운로드·복사 실패는 사유·개수를 기록한다. 디스크 부족·ZIP 구조 실패는 정상 완료로 표시하지 않는다.
5. 모든 메타 manifest 페이지를 확보하기 전 D09가 만료되면 기준 취득부터 다시 시작한다. 전부 확보한 뒤 사본 TTL이 지나도 로컬 고정 manifest로 작업할 수 있으나 서버 파일은 매번 현재 접근을 확인한다.
6. ExportJob의 기준·파일별 완료·해시·임시 경로를 로컬에 저장한다. 앱 재시작 시 무결성을 확인해 임시 작업을 재개한다. 기준/임시 자료가 없거나 손상되면 기존 정상 ZIP·원본은 보존하고 새 작업으로 시작한다.
7. 외부 저장 도중 중단돼 원자적 완료를 보장할 수 없는 파일은 불완전으로 안내한다. ZIP 종료·쓰기 완료·manifest/체크섬 검증 후만 완료한다.
8. 고정 기준 이후 새 데이터는 이번 ZIP에 자동 합치지 않고 새 백업에서 포함한다.

오프라인 완료 문구: “이 기기 기준 백업 완료 · 녹음 파일 N개 포함, M개 미포함 · 다른 기기의 최신 변경은 포함되지 않을 수 있습니다.” 미포함 0이어도 OFFLINE_PARTIAL을 전체 서버 최신 백업이라고 표시하지 않는다.
온라인도 파일 누락이 있으면 “백업 완료 · 일부 파일 미포함”과 상세를 제공한다. ZIP은 기존 설계대로 비암호화 개인 자료라는 안내를 유지한다.
영구 삭제 표식, 같은 백업의 반복 가져오기, 과거 고정/대표 값 덮어쓰기 방지는 기존 정책과 D07을 유지한다. 실제 파일·중단/복구 검증은 P21/P22에서 수행한다.
