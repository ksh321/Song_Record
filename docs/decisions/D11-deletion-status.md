# D11 — 탈퇴 상태 전용 확인증
- 상태: 확정 / P00-07 / 2026-09-16
- 사용자 승인: 추천 A, 접수 후 30일 유효
- 관련: R100·R101, V29·V30, P23·P24
- 사례: [P00-07 공통 사례](../contracts/P00-07-examples.md)

## 권한 경계
앱과 기존 소유 확인 외부 웹 경로에서 같은 삭제 서비스를 사용한다. 탈퇴 접수 즉시 일반 세션·새 음성 URL 발급·업로드를 차단한다. 별도 확인증은 해당 삭제 작업의 상태 조회에만 유효하며 계정 복구·로그인·취소·곡/메모/파일 접근을 허용하지 않는다.
상태 확인증은 운영상 30일 동안 유효하며 삭제를 30일 미루는 것이 아니다. 자동 연장·로그인 권한 복구는 없다. 확인증을 잃으면 A안에서 재발급/소유 확인 복구 기능은 제공하지 않는다. 접수 경로의 웹 상태 화면도 확인증이 있을 때만 사용한다.

## 접수 응답 유실을 해결하는 2단계
모든 경로 /v1. 확인증 준비는 탈퇴 접수가 아니며 계정을 차단하지 않는다.
1. 최근 재인증과 정상 Bearer/device_id로 POST /account/deletion-status-preparations. 서버는 준비 ID, 추측 불가능한 256비트 확인증 원문, 준비 만료 시각(10분)을 발급한다. 서버에는 토큰 해시만 보관하고 사용자/재인증/준비 ID에 결합한다. HTTPS 응답 이외 URL·로그에는 원문을 넣지 않는다.
2. 앱은 확인증을 보호된 저장소에 저장한 뒤 최종 탈퇴 확인을 받는다. 웹도 확인증 보관·분실 제한을 안내한다. 저장 실패 시 탈퇴 접수하지 않는다.
3. POST /account/deletion-requests에 준비 ID·base_revision·재인증 증명, Idempotency-Key를 보내고 전용 헤더로 확인증 소유를 입증한다. 준비 만료 및 재인증 유효성·소유권을 확인한다. 일반 인증을 계속 요구한다.
4. 같은 트랜잭션에서 DELETING 전환, 일반 접근 차단, 삭제 Job/원장, 확인증 활성화·accepted_at을 기록한다. 202와 operation_id·전용 상태 조회 경로·expires_at=accepted_at+30일 반환.
5. 접수 응답이 유실돼도 이미 저장한 확인증으로 준비 ID에 연결된 상태를 조회한다. 접수됐으면 일반 인증 없이 상태만 반환한다. 미접수이면 10분 준비 유효기간 내 PREPARED를 반환하며 일반 인증과 유효한 재인증으로 원래 명령을 재시도한다.
준비 응답 유실은 계정을 차단하지 않는다. 새 준비를 만들 수 있고 조회에 쓰이지 않은 준비는 10분 후 정리한다. 성공 결과 재현을 위해 토큰 원문을 영수증/로그에 저장하지 않는다. 준비 요청은 횟수 제한을 적용한다.

## 조회 API·재개
GET /account/deletion-status/{preparation_id}, X-Deletion-Status-Token 헤더. 해당 id와 확인증 해시가 일치해야 한다. 일반 Bearer로 대체할 수 없다.
응답은 status, accepted_at, service_deleted_at, backup_purge_due_at, completed_at, expires_at, retrying만 포함한다. 개인 식별자·이메일·파일명·객체키·삭제 대상 UUID 목록을 반환하지 않는다.
유효하지 않은 조합은 404, 유효한 확인증의 만료가 확인되면 410 STATUS_TOKEN_EXPIRED. 확인증/로그인 없이 이메일만으로 상태 검색 불가. 인증 헤더는 로그에서 제거하고 Cache-Control: no-store, 조회 횟수 제한을 적용한다.
앱 재실행 시 저장된 확인증으로 재개한다. 로그아웃용 일반 데이터 정리와 별도 보호 저장소 영역에 둔다. 백업 ZIP에 포함하지 않는다. 서버 재시작 시 영속 삭제 Job/최소 상태 레코드에서 계속 조회한다. 삭제 작업은 멱등 재시도하고 이미 삭제된 파일을 실패로 오인해 무한 반복하지 않는다.

## 상태·완료
| 내부 상태 | 화면 의미 |
|---|---|
| PREPARED | 아직 탈퇴 접수 전. 준비 만료 10분 |
| ACCEPTED / DELETING | 삭제 접수·처리 중. 일반 이용 차단 |
| BACKUP_CLEANUP | 서비스 DB/R2 대상 삭제 확인, 운영 백업 정리 중 |
| COMPLETED | 서비스 데이터 삭제 및 관련 운영 백업 정리 확인 |

장애는 진행 상태에 retrying=true를 표시하며 시간 경과만으로 COMPLETED로 바꾸지 않는다. 백업 최대 7일 정책이 지연되면 운영 경고·기한 초과 표시를 하고 완료라고 숨기지 않는다.
일반 서비스 DB 삭제 완료 판정은 최소 삭제 제어 기록까지 없어졌다는 뜻이 아니다. 제한된 상태 조회 레코드(임의 id, 토큰 해시, 시각·상태)와 삭제 방지 원장은 필요한 기간 별도 유지한다.
상태 레코드는 접수 30일 후 만료·정리하며 계정 식별 데이터에 대한 접근 경로를 남기지 않는다. 삭제 원장은 기존 정책대로 백업 소멸 확인 후 접수 기준 최대 30일 내 정리한다. 삭제 미완료 장애가 기한을 넘으면 경고·복구 대상으로 취급하고 완료를 위조하거나 미완료 작업을 자동 취소하지 않는다. 예외 기록의 실제 보존은 운영 사고 처리에 명시한다.
오프라인 기기 파일은 재연결 시 삭제 상태를 적용한다. 앱 밖 ZIP·M4A 사본은 회수할 수 없다. 이미 발급한 서명 URL은 기존 수명/객체 삭제에 따라 남을 수 있어 “접수 즉시 모든 사본·URL이 회수됨”으로 안내하지 않는다.
본 문서는 상태 전용 계약을 확정하며 실제 인증·장애·탈퇴 복구 테스트는 P23/P24에서 수행한다.
