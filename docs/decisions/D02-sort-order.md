- 관련: R022, X02, P03-08·P08-05·P17-03

## 공통 비교 규격 SR-SORT-1
표시 문자열은 변경하지 않는다. 별도 비교용 문자열과 구조화된 키를 만들며 앱(Dart)과 서버(Java)에 같은 규칙을 구현한다. 기본 DB collation이나 플랫폼 기본 locale 비교에 맡기지 않는다.

1. 비교용 값의 앞뒤 공백만 제거한다. 공백 집합은 U+0009~000D, 0020, 0085, 00A0, 1680, 2000~200A, 2028, 2029, 202F, 205F, 3000으로 고정한다. 내부 공백·구두점은 유지한다.
2. Unicode NFC로 정규화한다. ASCII A~Z만 a~z로 변환한다. 전각 문자 변환·악센트 제거·한자 독음 변환은 하지 않는다.
3. 첫 Unicode 스칼라 기준 그룹: 한글(0), ASCII 영문(1), ASCII 숫자(2), 기타 문자·기호(3), 빈 값(4). 한글 범위는 AC00~D7A3, 1100~11FF, 3130~318F, A960~A97F, D7B0~D7FF다. 정상 SAVED 제목·가수의 빈 값은 입력 검증에서 거절하며 빈 값 규칙은 방어용이다.
4. 그룹 안에서는 왼쪽부터 토큰을 비교한다. 연속 ASCII 0~9는 숫자 토큰, 나머지는 스칼라 하나씩 문자 토큰이다. 숫자끼리는 선행 0을 제거한 자릿수→숫자열로 비교한다(전부 0이면 값 0). 정수 자료형으로 파싱하지 않아 긴 숫자도 오버플로가 없다.
5. 숫자 토큰은 문자 토큰보다 먼저 둔다. 문자끼리는 Unicode 스칼라 값 오름차순이다. 이는 완성형 한글에서 가나다순이며 독립 자모·기타 언어는 발음순이 아닌 명시된 코드순이다.
6. 같은 숫자 값은 동률로 본다(2와 02). 다음 토큰을 비교하고 공통 접두사가 같으면 짧은 토큰열이 먼저다. 전체 비교키가 같으면 해당 목록의 다음 필드로 넘어간다. 원문 대소문자·선행 0·공백을 숨은 동률 기준으로 넣지 않는다.
7. 키 규격 버전 SR-SORT-1을 저장한다. NFC 구현은 공통 Unicode 17.0 정규화 데이터/테스트를 기준으로 선정하고 P03 시제품에서 대조한다. OS에 따라 다른 정규화 데이터에 무조건 의존하지 않는다. 규격 변경은 키 재생성·인덱스 갱신·커서 무효화가 필요하다.

구조화된 비교 규칙이 계약이다. DB용 바이트 키의 실제 인코딩·인덱스는 P03/P04에서 구현하며, 문자열 키를 단순 연결해 자릿수나 토큰 경계가 깨지지 않도록 공통 사례로 확인한다. 서버와 오프라인 신규 곡 모두 같은 키를 생성해야 한다.

## 내 곡 정렬 튜플
모든 정렬은 현재 계정 ACTIVE Song만 대상으로 한다. K는 위 비교키, ID는 아래 UUID 비교다.

| 정렬 | 비교 순서 |
|---|---|
| 최근 추가순 ADDED_DESC | created_at 내림차순 → id 오름차순 |
| 최근 녹음순 RECORDED_DESC | 연결 ACTIVE·SAVED 녹음의 max(recorded_at) 내림차순, 없는 곡 마지막 → id 오름차순 |
| 티어순 TIER | S/A/B/C/D/null 순 → K(title) → id |
| 곡명순 TITLE | K(title) → id |
| 가수순 ARTIST | K(artist) → K(title) → id |

최근 녹음순은 음성 파일 유무와 무관하다. 티어별 보기에서는 고정 티어 그룹을 먼저 적용한 뒤 각 그룹 내부에 선택 정렬을 적용한다. 전체/티어별 보기 전환은 검색어와 선택 정렬을 유지한다.

## UUID
UUID를 표준 16바이트로 해석해 unsigned 바이트 사전순으로 비교한다. Java의 signed long 비교를 그대로 쓰지 않는다. 하이픈 제거·소문자화한 32자리 16진 문자열의 사전순과 같은 결과여야 한다. UUID는 시각 추정용이 아닌 최종 동률 제거용이다.

## 대안과 검증
언어 정렬 엔진은 다국어 처리가 풍부하지만 양 플랫폼 엔진·데이터 버전 일치 부담이 있어 이번에는 채택하지 않는다. 단순 코드순만으로 숫자를 비교하는 안도 채택하지 않는다.
P00-05는 규칙·사례 결정 완료이며 앱/서버 비교 함수 시제품 검증은 P03-08에서 수행한다. P00-08은 이 사례를 전체 공통 fixture 세트에 합친다.
