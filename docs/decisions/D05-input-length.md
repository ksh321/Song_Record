# D05 — 입력 문자 수
- 상태: 확정 / P00-06 / 2026-09-16
- 선택: 추천 A(Unicode 코드 포인트). 사용자가 2~5번 변경을 지정했으며 1번은 앞선 추천안을 유지하는 것으로 처리.
- 관련: R018·R029·R078, P03-05
- 사례: [P00-06](../contracts/P00-06-examples.md)

## 규칙
UTF-16 코드 유닛 길이나 화면상 글자 묶음 수가 아닌 Unicode 코드 포인트 수를 센다. 잘못된 surrogate 입력은 거절한다. 앱 카운터와 서버 검증·DB 저장 한도가 동일해야 한다.

| 필드 | 저장 전 처리 | 허용 길이 |
|---|---|---|
| 곡명·가수 | 앞뒤 공백 제거 | SAVED 1~200, DRAFT 미입력 허용 |
| 플레이리스트 이름 | 앞뒤 공백 제거 | 1~100 |
| 사용자 태그 이름 | 앞뒤 공백 제거 | 1~50 |
| 기존 사용자 컨디션 이름 | 과거 자료 보존; 신규 고정 컨디션은 D06 | 기존 최대 50 유지 |
| 곡 아쉬운 점·녹음 메모 | 줄바꿈과 공백 보존 | 0~2000 |

trim 집합은 D02의 명시된 공백 집합을 사용한다. 메모의 CRLF와 단독 CR은 LF로 통일 후 센다. 앞뒤 공백을 제거하는 필드는 제거 후 길이를 검사한다. NFC/대소문자/기호 제거를 저장 입력에 강제하지 않으며 D02의 정렬용 키와 별개다. 따라서 분해형 한글은 구성 코드 포인트 수만큼 계산한다.
선택 메모의 null은 비어 있음을 뜻한다. PATCH 누락은 유지, null은 해제, 빈 문자열도 빈 메모로 허용한다. 필수 필드를 null로 변경해 SAVED를 무효 상태로 만들 수 없다.
초과 값은 조용히 잘라 저장하지 않는다. 입력 초안을 유지하고 필드별 오류를 표시한다. 한글 IME 조합 중 강제 절단하지 않고 최종 입력·저장에서 검증한다. 길이 오류는 400 INPUT_LENGTH_INVALID와 field/min/max/actual/unit=CODE_POINT를 반환한다. 메모 원문은 오류·로그에 넣지 않는다.
실제 앱/서버 코드 및 DB 경계 검증은 P03 이후 수행한다.
