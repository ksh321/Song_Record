## 1. 사용 원칙

이 문서는 설계서를 구현 가능한 요구사항과 검증 단위로 연결한다. 설계서나 코드구현계획서를 대체하지 않는다. 기존 계획서의 작업 범위·순서를 변경하지 않았으므로 이번 작업 때문에 계획서 DOCX를 수정할 필요는 없다.

요구사항의 구현 상태는 관련 작업과 증거를 확인한 뒤 진행 기록에서 관리한다. 아래의 “확인”은 앞으로 수행할 통과 기준이지 통과 결과가 아니다. V01~V48은 설계서 검증 번호, X01~X12는 계획서 추가 검수 번호다. 별도 검증 번호가 없는 규칙은 행에 적힌 경계값·실패 사례 자체가 수용 기준이다.

- ID는 삭제하거나 다른 의미로 재사용하지 않는다. 변경 시 이력과 관련 작업·검증을 함께 수정한다.
- 유형: 기능 / 상태 / 제약 / API / 검증. 여러 유형이 해당하면 함께 표시한다.
- 각 행의 작업 ID는 기존 계획서에 실제 존재하는 세부 작업이다. 한 요구사항에 여러 작업이 필요할 수 있다.
- 근거의 “설계”는 구현설계서, “UI”는 UI_REFERENCE, “팔레트”는 JSON을 뜻한다.
- 정리 과정에서 발견한 미결정 사항은 D01~D11로 분리한다. 제안을 확정 정책으로 구현하지 않는다.
- 충돌은 자료의 역할을 먼저 확인한 후 결정 기록으로 해소한다. HTML의 모의 데이터·임시 처리로 서버 정책을 정하지 않는다.
- 외부 서비스의 이용 조건·실제 월별 차트 확보·배포 시 플랫폼 정책 검증은 후속 작업이다. 이 문서 작성으로 확인 완료된 것이 아니다.

추가 확인 사항:

- GET /songs의 sort는 ADDED_DESC / RECORDED_DESC / TIER / TITLE / ARTIST이며 기본 ADDED_DESC다.
- 목록 후보 연결은 PATCH /playlists/{id}/items/{itemId}/song, 전체 순서는 PUT /playlists/{id}/order다.
- 태그·컨디션 archive와 녹음 tier/song 변경은 일반 필드 수정과 구분한다.
- 업로드 complete가 끝났다는 응답과 파일 검증 완료/STORED를 구분한다.
- /storage/requests는 D08의 제안 경로다. 확정 API인 것처럼 먼저 구현하지 않는다.
- 로그인 무효화 후 탈퇴 상태 조회 수단은 D11 결정 대상이다.
- 임의의 오늘 목록 API·TJ/KY 번호 자동 연결 API는 추가하지 않는다.
